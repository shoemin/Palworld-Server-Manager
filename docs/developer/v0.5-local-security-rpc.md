# Local security RPC adapter

Trial #42d3b binds the accepted local authentication and enrollment primitives to the additive `local_security.proto` service over standard gRPC on the Windows TLS named pipe. Protocol 1.1 advertises `LocalPrincipalSecurity`; the existing major-version and negotiated-feature gates both apply. Contracts contains only generated protobuf messages, enums and descriptors. The Host compiles its generated gRPC server stub separately, using Grpc.Tools `CompileOutputs=false`, so Contracts acquires no gRPC runtime dependency or new project edge.

The Windows listener installs the Host's connection middleware after TLS and before HTTP. Each actual connection owns one disposable session, one negotiation attempt and one authentication object. A semaphore serializes concurrent streams through that session. The native caller SID comes from the platform's named-pipe feature on every request, never a message field. A new connection must negotiate and prove its principal independently; request IDs cannot select another session. Closing the connection disposes its authentication state.

Before initialization, only negotiation and intended-user bootstrap completion are available. Afterwards, authentication and native-bound ticket completions remain available without an already-registered client key; enrollment creation and removal require the current authenticated Owner and the existing transaction-time authorization checks. Rotation/re-home completion requires the previously privileged-prepared ticket. No ordinary Owner setter, offline preparation, machine recovery, operational executor or remote listener is exposed. Successful identity proof returns only principal identity and Owner status, without inferring capability grants.

The composition must configure gRPC receive/send bounds to `MaximumMessageBytes` (16 KiB), disable detailed errors and avoid request-body logging. Inputs have additional identity, signature, public-key and secret bounds. Public protocol-major mismatch details remain specific; authentication/ticket, malformed-input, precondition and internal errors are sanitized. Owned temporary bearer copies are cleared; generated protobuf and gRPC serialization buffers remain runtime-owned and must never be logged. Native mismatch reporting carries only the existing failure enum.

Completion preserves the repository's durable consumed-ticket behavior: an old matching secret confirms its recorded principal ID without re-registering the submitted key. The final client must therefore use the [durable ceremony store](v0.5-client-credential-ceremony.md), prove the prepared key authenticates that returned principal, confirm the binding durably, then delete the protected handoff. An ID-only reply is insufficient.

The real named-pipe/TLS/gRPC probe covers pin failure before request delivery, incompatible/missing negotiation, uninitialized restrictions, bootstrap/retry/authentication, fresh-connection refusal, nonce replay/concurrency, native mismatch, Owner-only enrollment/removal, rotation/re-home and audit-failure rollback with sanitized errors. Synthetic native-account setup and direct repository preparation are explicit test fixtures. The [production Host service](v0.5-host-service-composition.md) now exposes this adapter; ordinary-client wiring and final actual two-user ceremonies remain #42d3c2/c3; this adapter does not independently complete #42.
