# Windows public Host trust and local TLS adapters

This Astra #42b2 unit implements the public artifact and Windows transport seams from [architecture section 3b](v0.5-architecture.md#3b-authenticated-local-host-channel-product-decision-2026-09-01-local-004). The seam alone does not complete #42; the later bounded units implement executable composition, reconciliation, authentication and enrollment/recovery, with [final actual Windows qualification](v0.5-windows-local-security-qualification.md). A native OS SID is identity evidence, never permission or enrollment approval.

## Public artifact

The trusted Host/offline caller supplies `LocalHostTrustPublication`, derived from SQLite under the existing machine exclusivity lease. The version-1 UTF-8 JSON artifact `local-host-trust.json` has exactly five fields: `schemaVersion`, `hostId`, `currentHostCredentialFingerprint`, `pendingHostCredentialFingerprint`, `pendingRotationId`. Fingerprints are uppercase SHA-256 of DER SubjectPublicKeyInfo for the P-256 key, not the certificate encoding. Both pending fields are null or both populated. Empty identities, invalid fingerprints, unknown/duplicate fields and oversized input are rejected. The client-side parser has no dependency on Host contracts, Core or persistence.

Elevated provisioning creates the dedicated public directory with a protected ACL: the specific service SID, Administrators and SYSTEM have full control; Everyone has read/traverse only. Publication files have the same explicit writers and public read only. Public artifacts contain no secret. The directory must be outside the private Host database directory and its ancestors must permit public traversal. Ancestor owners and destructive access, final ownership/protection, mandatory ACL entries, unsupported/callback ACEs and reparse paths are checked. Existing unsafe objects are rejected, never silently adopted. File ACLs are checked on the opened handle.

The publisher validates its inputs and existing artifact, writes a unique protected temporary file, flushes it and uses same-directory replace/write-through rename. Replacement has a bounded retry for Windows sharing/access failures while readers close prior handles, revalidating the protected target between attempts. It never deletes the target first. A subsequent publication retires only its reserved, validated temporary artifacts. Cancellation before rename preserves the previous artifact; after the commit point a completed publication may already be visible. The in-process publication gate complements, and does not replace, the caller's machine-wide lease.

This file operation is not atomic with SQLite. The [production coordinator](v0.5-host-service-composition.md) commits authoritative identity/rotation state first and publishes from that state before serving any connection, on every startup. It reconciles both current and pending values, including clearing pending after Aborted, CutOver or Completed. The publisher neither selects a credential nor treats this public file as authoritative recovery input.

## Standard TLS over a local named pipe

The Host Windows adapter configures only a named-pipe listener with HTTP/2 and TLS 1.2/1.3. The pipe has the accepted explicit service/Administrators/SYSTEM privileges, activation-group read/write and Network denial. The certificate is supplied from the [approved native cache](v0.5-native-tls-cache.md). The adapter opens no TCP endpoint and creates no machine key. Native caller SID extraction uses the named-pipe connection feature with identification-level impersonation for the read only; no privileged work runs under impersonation.

The client factory accepts only exact HTTP/2 requests to `https://localhost` on port 443; this is the logical URI, never a TCP connection. It disables proxies, redirects, cookies, renegotiation and TLS resumption. It reads the protected descriptor before connecting and again in certificate validation on each new connection, checks expected HostId and current-or-pending SPKI pin, then lets HttpClient complete standard TLS before any HTTP headers/body are sent. The concrete file reader avoids capturing a synchronization context because the standard certificate-validation callback is synchronous. Existing authenticated pooled connections remain usable; new connections re-read trust. The handler owns connection disposal.

Missing descriptor and missing pipe have distinct errors. Once a pipe connects, failed TLS or an internally timed-out handshake produces an explicit local-authentication error, never the dormant-endpoint classification. Caller cancellation is preserved. Post-handshake HTTP failures remain HTTP failures. The adapter does not activate a Host or retry trust errors; the [ordinary-client coordinator](v0.5-client-security-composition.md) preserves that distinction.

## Evidence and limits

The ordinary suite covers schema failures, missing-then-created paths, protected file/ancestor ACL rejection, wrong HostId/pin with no handler delivery, staged/current pins, orphan cleanup, cancellation, missing endpoint, plaintext squatter and silent TLS endpoint. The explicit privileged Windows suite adds a real virtual-service publication/TLS connection, two actual nonadmins able to read but denied write/delete, and dangling-symlink rejection; it retains native-cache lifecycle and service/multi-user tests. The trial ledger records actual run results; test definitions alone are not a PASS.

These are channel and storage primitives. Synthetic TLS requests do not prove principal enrollment, Owner recovery, production bootstrap, real reboot, Palworld operation or release qualification.

The handshake-completion marker uses the documented [SocketsHttpHandler extension-point ordering](https://devblogs.microsoft.com/dotnet/net-5-new-networking-improvements/): the plaintext filter runs after TLS completes and before HTTP is sent. The client explicitly sets [AllowTlsResume](https://learn.microsoft.com/en-us/dotnet/api/system.net.security.sslclientauthenticationoptions.allowtlsresume?view=net-8.0) to false; this option is available in the repository's .NET 8 runtime.
