# Generation-owned recovery completion

Trial #28n connects the [fixed recovery sender](v0.5-recovery-completion-sender.md) to `HostNetworkGeneration.ConfirmRecoveryAsync`. The trusted Windows composition supplies the same native TLS transport and Host certificate used by that generation's other peer clients. Configuration creates the sender once; work is accepted only while the configured generation is serving. The [reverse client](v0.5-recovery-completion-pull.md) uses the same ownership through `PullRecoveryAsync`, covering both fresh connections and their local receipt checks.

The existing `HostTrafficLifetime` admission covers the entire awaited exchange, including its final persistence checks and native callback/channel/transport disposal. Shutdown closes admission and requests cancellation, then awaits actual work completion before disposing the generation's certificate. Cancellation or the sender deadline cannot bypass that drain. There is no second shutdown mechanism, key deletion, new trust writer, grant issuance, protocol change or ordinary recovery authorization.

Four test groups cover the actual Windows composition sending and confirming once, a duplicate with no pending work, refusal after shutdown; a real native TLS callback held across shutdown while the certificate remains live; a controlled lost response after the peer commits, followed by a fresh same-key generation retrying the original durable approval with one audit per effect; and before-start, unconfigured and stopped admission. The restart uses a fresh runtime over the same database. The local outgoing-only fault fixture does not create a separate listener borrowing the generation-owned certificate. These tests use canonical Owner approvals over explicit historical binding fixtures, not a full PAKE ceremony. Controlled Host-side callback/response holds are not actual remote process/network hang qualification.

The separately qualified [contact coordinator](v0.5-recovery-contact-retry.md) now retries after authenticated contact in existing fixed security clients. Generation shutdown also seals and drains that coordinator before key disposal. Parent #28 still requires public initiation and actual remote process/network hang/drop; the separate native lifecycle qualification is linked below. Creator permissions and limits remain approved; accessibility/screen-reader certification remains WAIVED, never PASS. No physical server, Windows parity, Linux or release qualification is claimed.

The Astra trial used no external GitHub Codex reviewer. Astra was responsible for both implementation and technical review.

The separate [native revoked-relationship repair qualification](v0.5-native-repair.md) now connects genuine PAKE, separate local Owner approvals, fresh configured roots and this generation-owned sender. [Native simultaneous own-key recovery](v0.5-native-own-recovery.md) separately qualifies old-generation shutdown, actual new keys/fresh PAKE and the carried approval across independent recovery clears. Public initiating commands, contact retry and actual remote faults remain separate parent requirements.
