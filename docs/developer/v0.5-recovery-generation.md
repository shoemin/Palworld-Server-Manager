# Generation-owned recovery completion

Trial #28n connects the [fixed recovery sender](v0.5-recovery-completion-sender.md) to `HostNetworkGeneration.ConfirmRecoveryAsync`. The trusted Windows composition supplies the same native TLS transport and Host certificate used by that generation's other peer clients. Configuration creates the sender once; work is accepted only while the configured generation is serving.

The existing `HostTrafficLifetime` admission covers the entire awaited exchange, including its final persistence checks and native callback/channel/transport disposal. Shutdown closes admission and requests cancellation, then awaits actual work completion before disposing the generation's certificate. Cancellation or the sender deadline cannot bypass that drain. There is no second shutdown mechanism, key deletion, new trust writer, grant issuance, protocol change or ordinary recovery authorization.

Four test groups cover the actual Windows composition sending and confirming once, a duplicate with no pending work, refusal after shutdown; a real native TLS callback held across shutdown while the certificate remains live; a controlled lost response after the peer commits, followed by a fresh same-key generation retrying the original durable approval with one audit per effect; and before-start, unconfigured and stopped admission. The restart uses a fresh runtime over the same database. The local outgoing-only fault fixture does not create a separate listener borrowing the generation-owned certificate. These tests use canonical Owner approvals over explicit historical binding fixtures, not a full PAKE ceremony. Controlled Host-side callback/response holds are not actual remote process/network hang qualification.

Parent #28 still requires opportunistic authenticated-contact retry, public initiation and full native fresh-pairing/two-Owner approval/recovery lifecycle evidence, including actual remote hang/drop. This bounded lifecycle component does not finish those requirements. Creator permissions and limits remain approved; accessibility/screen-reader certification remains WAIVED, never PASS. No physical server, Windows parity, Linux or release qualification is claimed.
