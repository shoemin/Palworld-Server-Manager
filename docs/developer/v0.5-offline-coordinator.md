# Offline bootstrap and recovery coordinator

Trial #42d2c composes the existing Windows security, persistence, machine-trust and intended-user handoff foundations in `Host.Cli`. The installed service must already exist and be stopped. The shipped executable selects the one product service and machine data location; alternate paths/names exist only as trusted composition parameters for isolated integration tests, with no CLI configuration override.

The bounded command surface is:

```text
PalworldServerManager.Host.Cli.exe bootstrap --owner-sid S-1-5-21-...
PalworldServerManager.Host.Cli.exe rotate-owner
PalworldServerManager.Host.Cli.exe rehome-owner --owner-sid S-1-5-21-...
PalworldServerManager.Host.Cli.exe recover-machine --reason loss
PalworldServerManager.Host.Cli.exe recover-machine --reason compromise
```

Every operation requires an enabled Administrator token, a stopped service and the immediate machine-wide persistence lease. Service state is rechecked after acquiring the lease. Supplied recipient SIDs must resolve to exact user accounts before setup writes; rotation obtains its intended SID from the persisted current Owner. Host root/ancestor/reparse and every existing state object's privileged ACL/owner are validated without adopting or repairing unsafe files. Inherited unprivileged access is rejected too. Only then can migration and identity initialization open SQLite.

Every invocation attempts authoritative current/pending publication and native/secret cleanup before new privileged work. A precise missing-public-metadata failure remains fatal to ordinary commands but can be repaired by explicitly requested fresh machine recovery without reading Old's private key or trusting the descriptor. Unknown references, retired authoritative material, malformed identity and unknown rotation state remain distinct failures. Startup service composition is completed separately in #42d3.

Initial bootstrap creates a tracked P-256 credential only if no current credential exists, publishes it, provisions the independent HMAC key and native service key-creation permission, then prepares a recipient-bound ticket. It creates zero Owner authority offline. Rotation/re-home prepare their existing snapshot-bound tickets. Each writes a protected handoff before committing only its keyed verifier and metadata; a failed ticket transaction deletes exactly that new handoff. An unexpired initial ticket cannot be silently retargeted. Successful output contains only public Host/ticket/recipient/purpose/expiry metadata. Private buffers are cleared and diagnostics never copy exception messages or input payloads.

Machine loss/compromise recovery creates a fresh tracked credential, commits the existing reason-specific recovery transaction, then publishes and retires stale native/secure-store material. It never validates or reads Old's private credential. Both triggers retain HostId, Owner/local-principal authority and the independent enrollment HMAC key. Existing remote relationships remain recovery-required; this coordinator performs no pairing or remote authorization.

After a credential-selection commit, the publication barrier keeps the machine lease and retries until publication and cleanup succeed. Cancellation, cleanup errors and a broken diagnostic stream do not release it. Ctrl+C requests cancellation rather than immediately terminating the process, so it cannot interrupt that committed barrier. A genuine forced process termination/power failure retains the architecture's disclosed cross-store crash window; the next Host startup or any offline invocation reconciles it. No cross-store atomicity is claimed.

Ordinary tests cover bounded command parsing and a held real lease across publication failure, cancellation, cleanup failure and broken diagnostics. Windows integration runs the actual production command handler under an elevated token, with a real SCM service/lease and separate non-admin process, against isolated roots. It checks pre-write refusals, zero-Owner bootstrap preparation, no live retargeting, intended-user delivery, failed-audit cleanup, both recovery reasons, physically missing old keys, missing legacy public metadata, native retirement, HMAC preservation and stale-publication repair during an unrelated command. The recovery-preparation fixture seeds an Owner transactionally; it is explicitly not the final online ceremony. Production service/client protocol wiring and actual end-to-end bootstrap/Owner recovery remain #42d3; full #42 is incomplete.
