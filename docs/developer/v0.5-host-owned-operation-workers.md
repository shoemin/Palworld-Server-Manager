# Host-owned operation workers

Trial reference: #46d. The internal Host runtime owns trusted, code-registered operation executors and their task lifetime, using the [atomic operation repository](v0.5-durable-operation-lifecycle.md). It is a framework component; installation into production composition, explicit startup recovery execution and client Activity contracts remain subsequent #46 work.

Admission commits the operation record and lock before dispatch. Its cancellation token applies only through that admission transaction. Accepted work receives the runtime's own shutdown token; client disconnect and cancellation of an observational wait cannot cancel it. Task dispatch suppresses ambient execution context, so request-local state does not flow into an operation by accident. Failed/unknown/canceled admission dispatches no worker, and a reused durable ID cannot dispatch twice.

Each executor receives a context scoped to its operation. Phase changes and heartbeats compare its current revision and require an explicit trusted current-authority callback. The context is sealed when the executor returns or throws; retaining a reference cannot authorize later writes. A competing trusted repository write makes the old context stale. Actual operation authors remain responsible for current business authorization, durable inputs, audit and all effects; neither a lock nor this context grants authority. Executors must await all work they own and publish a terminal phase only after actual resolution. These trusted callbacks are not a sandbox or request-controlled code.

An exception or a return while the record is nonterminal retains the record/lock and surfaces Recovery Required. No generic catch marks work Failed, discards artifacts or releases exclusion. Raw exception messages do not appear in observations or logs. Read-only observations combine authoritative persisted state with the current runtime's actual task set; a finished task is not proof that an operation durably resolved.

Shutdown first refuses further admission, signals its token, and waits for the actual tracked tasks. An executor that still owns work delays shutdown until it returns. Even a throwing cancellation callback does not skip this drain. Completed tasks are pruned only after completion is observable, never from inside their still-running finally blocks. The enclosing Host must retain its machine-wide lease through runtime disposal. Worker lifetime belongs outside client connections and replaceable network/listener generations.

Construction inspects every stored Host/server operation. Terminal history is Resolved. Existing nonterminal work is never labeled Running merely because policy metadata matches. Manual/unknown/inconsistent work is Recovery Required; other known dispositions are Awaiting Recovery. No startup executor is invoked in this unit. The following recovery unit must apply each code-defined phase's explicit retry/resume/discard rule; this intermediate component does not satisfy that whole-#46 acceptance criterion by inspection alone.

Nine representative self-test scenarios cover client/wait cancellation, actual shutdown drain with retained state and reopen, failed/unfinished workers, eight competing admissions with one execution, ambient request isolation, all four dispositions across Host/server startup targets, stale external transitions, cancellation-callback failure with drain, and simultaneous admission/shutdown with no lost accepted worker. They use real SQLite state and the fixture's writer lease. They do not claim installed operation RPCs, physical Host restart, real Palworld operations or a concrete destructive recovery policy.

No schema, grant, credential, client dependency, wire protocol or production composition change. No offline queue. Accessibility WAIVED, never PASS; Windows parity, physical/Palworld/Linux/release gates remain. The Astra trial used no external GitHub Codex reviewer. Astra was responsible for both implementation and technical review.
