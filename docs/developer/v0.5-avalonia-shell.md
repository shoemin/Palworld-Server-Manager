# Avalonia shell

Trial reference: #52b. `MainWindow` implements the accepted #34–#38 shell over [Host-qualified shell state](v0.5-shell-state.md). Production starts disconnected with no fabricated inventory, status, progress or operation count. Add/Import and server feature tabs have persistent unavailable explanations until later Host contracts supply supported, authorized data. The five tabs are entry-point placement only; this is not #53 or #54 feature completion.

The permanent rail groups authorized rows by exact HostId. All Servers and This PC change the model scope. Native tree items retain automation semantics, full identity names and a shell-specific template so themes cannot change indentation. Arrows/Home/End inspect; Left/Right expand or collapse groups; Enter and pointer activation request exact-target revalidation. Tab enters at the last inspected visible item and leaves the tree. Compact inspection reveals selectable full Host and server UUIDs without selecting. Closing identity, expanded rail or global panels preserves selection and returns focus. Binding another view cancels old selection work and rejects stale status updates.

The 280-unit rail collapses to 88 below 1200; the 304-unit Activity/Alerts/Settings panel overlays at narrow widths without a blocking backdrop. The rail can temporarily expand. Global controls reflow without disappearing. At 640 units and 200% text, compact controls retain full accessible names, the rail still has scrollable rows, and the five tabs scroll with explicit controls. A shell-specific two-unit accent focus adorner remains separate from selected fill. Refined alone adds original angular corner lines; minimal themes change semantic tokens with otherwise identical geometry. System Segoe UI/Arial replaces the scaffold's bundled Inter font.

The shell is static: it introduces no animation, and also disables Fluent template transitions. Reduce-motion preference starts enabled; turning it off does not introduce optional motion. Appearance controls currently affect the current view only; persistence and other Manager settings are not implemented by this unit. [Local connection UI](v0.5-avalonia-connection.md) uses the accepted authenticated client/activation path; no new inventory RPC or client-side server operation is invented here.

## Validation

`dotnet run --project tests/PalworldServerManager.Client.UiTest -c Release` runs the actual client assembly through same-version Avalonia.Headless with Skia drawing enabled. The test uses Avalonia keyboard and pointer input, waits for layout/render before hit-testing, and saves real frames under `build-logs/shell-renders`. `scripts/build.ps1` includes it after ordinary tests. This follows the [Avalonia headless platform](https://v11.docs.avaloniaui.net/docs/concepts/headless/) mechanism; it is not an HTML recreation or a static design generator. Tests use synthetic authorized-inventory inputs and a test selector, never real server authority.

Assertions cover exact selection versus focus, native grouping, scope filtering, identity disclosure, panel focus return, nonmodal Tab behavior, rail expansion, revoked-row removal, stale view failures, enlarged controls/tab scrolling, absent production fixtures, no transitions and identical tree geometry for all themes. A two-minute process deadline bounds harness failures. Window cleanup runs before the harness exits; no service, OS user, credential or machine configuration is created by these UI tests.

[Rendered evidence](../design/astra-52-shell/README.md) records actual local Windows/Skia frames for three widths/themes plus identity and enlarged-text states. [Actual UI/service qualification](v0.5-avalonia-windows-qualification.md) separately exercises production activation/authentication under real OS users. [Native functional qualification](v0.5-avalonia-native-qualification.md) exercises ordinary window and panel/theme behavior. The Product Owner waived screen-reader/OS high-contrast certification for this trial; this is a revised acceptance contract, not an accessibility PASS. Full #52 acceptance and exact review state are recorded in the trial ledger.
