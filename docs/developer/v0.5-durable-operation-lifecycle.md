# Atomic durable operation lifecycle

Trial reference: #46c. The trusted Host repository persists operation records and their independent exclusive locks atomically. It uses the [operation definitions](v0.5-operation-definitions.md) and retains the separate [editable-resource revision seam](v0.5-resource-revisions.md). Worker ownership, startup disposition application and client Activity RPCs remain later #46 units.

Schema12 preserves existing operation tables/rows and adds nullable definition fingerprint/lock requirement, a record revision and checked global operation-state revision. Old rows retain unqualified metadata; no None lock or safe resume classification is manufactured. Definitions have a positive semantic version (initial1) and deterministic fingerprint of the kind/version/lock/initial phase and sorted phase/disposition/transition declarations. This is not app-version negotiation. Concrete executor authors must advance the semantic version when phase meaning changes; the fingerprint also detects declaration changes independently of collection construction order.

Start validates the initialized authoritative Host and trusted same-transaction authority callback, rejects reused IDs and conflicting scopes, and commits the initial record with its lock in one immediate transaction. None uses no lock. A server-targeted HostExclusive operation retains its real ServerRef while holding HostScope. Independent server locks coexist; Host/server conflicts are symmetric and scoped to the destination Host. Read-only repository observations expose the same durable records/locks to independent readers.

Transition compares the operation's current record revision and allows only declared phase edges. Heartbeat keeps phase and exclusion unchanged; its timestamp never moves backward. Terminal phase and lock release commit in the same transaction. The repository verifies current policy, exact owning-record/lock relationship, state revision and exact changed record before commit. Stale writes, conflict, authorization refusal, SQL/late-state faults, exhaustion and cancellation roll back. No connection-bound disposable lease, TTL expiry, automatic retry or offline queue is added.

Authority callbacks are trusted read-only Host code, invoked before and after changes inside the supplied transaction; they cannot commit, roll back or dispose it. They are not request fields or a sandbox. The framework does not infer permissions from lock type or supply a business audit/executor. Actual operations must enforce their own current authority and business audit at the relevant boundary.

Valid-shaped unknown/changed active policies, incompatible target/requirement or missing/inconsistent locks set HasUnqualifiedState and prevent ordinary lifecycle mutation; rows and locks remain intact for explicit recovery. Malformed persisted identities/state fail closed. Unsupported terminal history with no lock stays history. Matching metadata establishes structural qualification only: it does not prove a worker is still running or authorize automatic resumption after a crash. Startup recovery must separately apply each interrupted phase's declared disposition and expose ambiguous work as Recovery Required.

Eight scenarios cover stable/changed definition fingerprints, qualified targets and full conflict hierarchy, shared read observations, eight competing admissions and phase writers,10 trigger-fault rollback/retry cases, early/late authority and cancellation, historical schema upgrade/unknown policy preservation, exhausted/altered revisions and collateral writes. Eight real child-process termination cases cover HostScope and ServerScope before/after admission commit and before/after terminal commit, under actual exclusive writer leases; reopening finds both record/lock or neither, or a nonterminal locked record versus a terminal unlocked record. These are disposable repository-process fixtures, not physical reboot, installed operation RPCs or Palworld execution.

Accessibility WAIVED, never PASS; physical Windows parity/Palworld/Linux/release gates remain. The Astra trial used no external GitHub Codex reviewer. Astra was responsible for both implementation and technical review.
