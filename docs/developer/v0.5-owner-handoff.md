# Protected Owner handoff foundation

Trial #42d2b implements the Windows artifact boundary shared by initial bootstrap, Owner credential rotation and Owner re-home. The privileged writer enforces an elevated Administrator token and resolves the recipient SID to an exact Windows user account. The ordinary reader derives its recipient from the current Windows token; it has no other-user SID argument and no Host-side dependency.

The trusted composition root supplies a local handoff directory outside Host persistence and the Host secure store. Its protected root grants Administrators/SYSTEM full control and everyone read/traverse access without inheritance. Each SID directory grants only that recipient read/traverse access and Administrators/SYSTEM full control, again without inheritance. Ancestors must have trusted owners and no unprivileged replacement rights; reparse paths fail closed. Existing unsafe directories are rejected, never adopted or repaired.

Each ticket is a unique `TicketId`-named file created with its final protected DACL and an exclusive handle. Only the intended SID receives file read access, plus deletion. Administrators/SYSTEM receive write, ACL maintenance and deletion rights but no `ReadData` grant. The recipient cannot write file contents or create replacement entries. The privileged creator already holds the raw secret in memory; as with the accepted Windows threat model, privileged machine owners can change ACLs, so this does not claim protection against them deliberately exercising that authority.

The writer refuses to overwrite an existing ticket. It flushes the entire payload through a write-through handle before closing it; a failed write cleans up only that newly created artifact. A hard crash can leave a malformed partial file, which the reader rejects. The artifact is exactly 73 bytes: `PSMOH001`, 16-byte .NET Guid representation for HostId, 16 bytes for TicketId, one purpose byte (1 bootstrap, 3 rotation, 4 re-home), and a 32-byte secret. Unknown purpose/version, wrong expected identities and every other length are rejected. Client parsing is independent of Host assemblies, exports secret bytes only through an explicit method, redacts string conversion and clears its retained secret on disposal. Callers must clear exported/read buffers after use.

The [offline coordinator](v0.5-offline-coordinator.md) holds the machine lease, writes the handoff before committing its verifier-only ticket, and deletes that exact artifact if ticket preparation fails. A crash before ticket commit may leave an artifact with no authority; it must not silently retarget or replace a live bootstrap ticket. The [ordinary client](v0.5-client-security-composition.md) authenticates the Host before sending anything and deletes the handoff only after confirmed consumption and [durable client credential binding](v0.5-client-credential-ceremony.md). Reader deletion is idempotent. The shared client coordinator implements that ordering; [actual final two-user Owner ceremonies](v0.5-windows-local-security-qualification.md) now qualify the composed Windows boundary.

Validation includes malformed framing and secret-redaction checks plus explicit Windows integration using an elevated creator and two real non-admin users. The recipient reads/deletes all three purposes; the second user has product-group eligibility but is denied direct OS read access. Tests also exercise recipient write/create denial, non-elevated writer denial, elevated no-overwrite behavior, broad ACL rejection, partial payload rejection, and reparse cleanup without touching the target. Integration results must pass before this bounded artifact foundation can be accepted; it does not independently complete #42.
