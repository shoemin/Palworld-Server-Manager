# Machine-trust reconciliation foundation

Trial unit #42d2a supplies metadata, material and reconciliation seams for the Windows Host and privileged offline coordinator. The [offline coordinator](v0.5-offline-coordinator.md) and [production Host service](v0.5-host-service-composition.md) now consume these seams. [Routine rotation preparation](v0.5-rotation-preparation.md) adds serialized reservation/staging-readiness/abort; peer staging, cutover and retirement policy remain later scope. The accepted architecture remains authoritative.

`HostIdentity.CurrentCredentialRef` in SQLite selects the credential. Migration 2 adds public SPKI fingerprint and activation metadata to `SecureCredentialReferences`; neither column contains private material. An upgrade preserves existing identity and activation history and does not infer fingerprints from an untrusted descriptor. Missing required public metadata fails closed. Explicit machine recovery can replace a missing old credential without reading its private material.

The caller records a unique planned reference before creating its P-256 credential through `WindowsHostCredentialMaterial` and the existing secure store, then records the returned public fingerprint. This order makes abandoned creation discoverable. Only an unused, unretired reference can become current. Recovery also rejects a previously activated or staged key repackaged under another reference. Initial installation requires an uninitialized Host without a current credential. Neither operation creates an Owner.

Loss and suspected compromise use the same offline metadata transaction: select the fresh credential, abort every nonterminal rotation (including `CutOver`), mark active peers recovery-required, and append a distinct reason-specific audit event. An audit failure rolls everything back. Owner identities, principal keys and grants are unchanged. No online adapter exposes this operation, and old private material is never required to authorize, validate or perform it.

The public projection follows these states:

| State | Published current | Published pending | Retained material |
|---|---|---|---|
| Prepared | Old | None | Old and New |
| Staging / ReadyForCutover | Old | New plus rotation ID | Old and New |
| CutOver | New | None | Old and New until completion |
| Completed | SQLite current | None | Current |
| Aborted, including offline recovery | SQLite current | None | Current |

Conflicting current/rotation metadata, missing required fingerprints, unknown states and multiple nonterminal rotations fail closed. Prepared may retain a reserved New reference whose fingerprint is still null, publishing only Old; it cannot stage or present that reservation. A non-null malformed fingerprint remains an error, and all later states require complete, fresh New metadata. This projection does not decide whether cutover or peer completion is allowed.

`HostTrustReconciler` publishes the derived descriptor first, reconciles the derived native cache second, then deletes unused tracked secrets and records retirement after each successful deletion. Missing material is an idempotent success. A failed publication performs no retirement; failed cleanup remains retryable. Abandoned planned references with no material are cleaned up too; a live Prepared reservation is retained. The independent enrollment HMAC key is outside the TLS registry and is never retired by this process. It may be initially provisioned only without any ticket history; a missing key with retained ticket history, or a malformed existing key, fails closed rather than breaking consumed-ticket retries through regeneration.

The executable caller must hold the machine lease and quiesce connections and credential mutations for the whole pass. Before listening it must validate the selected private credential against authoritative public metadata and load the native TLS cache. Offline recovery must not validate or read the outgoing private credential. The [Host.Cli coordinator](v0.5-offline-coordinator.md) enforces actual elevation and exclusivity, reconciles at every invocation, and retains its lease while retrying publication after a committed recovery. The single-pass seam does not itself provide those executable lifetime guarantees. A hard crash between SQLite commit and descriptor publication retains the residual exposure documented in architecture section 3b; startup or the next offline invocation repairs it.

Four self-test groups cover v1 upgrade, all rotation states, both recovery reasons, audit rollback, fresh-key enforcement, publication/cleanup failure ordering, abandoned-material cleanup, independent HMAC lifetime and a store that throws on any old-private read. The existing real Windows service/multi-user harness now generates and validates its credential through the new material adapter. That harness remains synthetic protocol traffic: the offline coordinator has separate Windows qualification; [final bootstrap/Owner recovery qualification](v0.5-windows-local-security-qualification.md) now supplies separate shipped-client evidence.
