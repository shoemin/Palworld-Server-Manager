# Host traffic lifetime and draining

Trial reference: #44u, within #44. `HostTrafficLifetime` owns admitted connection and whole-operation scopes for one credential generation under the existing machine lease. Draining atomically closes admission, signals cancellation outside its state lock, and waits for every admitted scope and cancellation callback to finish. Repeated drain calls share the same completion. Once closed it can never reopen, including after a failed callback; failure is reported only after admitted work exits. Uncooperative work keeps draining incomplete, so a caller cannot treat a timeout as proof that releasing a key is safe.

The Windows local, pinned-peer and first-contact pairing builders accept the same trusted connection middleware before TLS. This covers connections that never finish a handshake, as well as active HTTP/2 requests. Cancellation aborts those connections, but the scope remains until the complete connection pipeline exits. A real blocked transactional RPC test proves that an aborted client connection cannot make draining finish while its Host mutation is still running. The application and borrowed credential remain owned until draining and application disposal finish.

The installed Windows local service uses this lifetime during shutdown. It observes both service cancellation and unexpected application stopping, closes traffic, drains it, and then stops/disposes the application before disposing the credential and machine lease. A failure still attempts application shutdown and remains a service failure. No new listener or ordinary authority surface is enabled.

Outgoing operations and background mutations must use the whole-operation wrapper, covering all follow-up persistence, audit/finally work and transport disposal. Wrapping only an HTTP transport would miss work performed after that transport exits. The real activation test holds a post-reply mutation open and proves draining waits for it. This unit supplies the wrapper and shared composition seams; a following generation owner must route every outgoing/background operation and every listener through one lifetime. Existing standalone trusted fixtures remain independently owned.

Seven ordinary scenarios cover canceled work and awaited cleanup, concurrent admission/idempotent terminal state, cancellation callback failure, actual local and peer connection shutdown, actual outgoing post-reply mutation, actual aborted inbound database work, and partial TLS across all three listeners. The partial-handshake pairing provider throws if reached; that scenario proves transport ownership, never PAKE success. Tests retain synthetic authority setup and existing activation hooks.

Draining is neither authorization nor an operation lock or a cutover permit. The final cutover transaction must still revalidate Owner, current proposal, every peer and remaining acceptance time. Complete multi-listener generation replacement, installed initiation, retirement and full crash/physical acceptance remain outstanding.
