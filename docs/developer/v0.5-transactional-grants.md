# Transactional grant persistence

Trial reference: #45b. This bounded unit persists the [canonical authorization foundation](v0.5-authorization-foundation.md) through a trusted Host repository. #45 remains incomplete for authenticated incoming Host adapters/dispatch. Later engine slices cover [configured defaults](v0.5-configured-defaults.md), [presets](v0.5-canonical-presets.md) and [Owner historical reissue](v0.5-historical-grant-reissue.md); complete credential-replacement integration remains separate. No server operation or UI is enabled. The [approved six-permission creator policy](v0.5-creator-grants.md) supplies the Host confirmation/grant seam; actual server-creation workflow integration remains downstream. [Authenticated remote grant writers](v0.5-remote-grants.md) add the trusted incoming peer repository paths; Host RPC/outbound integration remains separate.

`GrantPolicyRepository` requires the existing machine lease to be held by its Host caller. It opens an existing database, never initializes or repairs one. `Read` uses one SQLite snapshot for the Host identity, exactly one active Owner on an initialized Host, active local principals, Active non-recovery peers, both typed grant forests and their revision. Unknown capability strings, malformed identities or missing revision metadata fail closed. A numeric string is not an accepted enum name. The returned grants are read-only immutable domain values; the snapshot is neither caller authentication nor permission to commit a later write. This trusted fact seam is not an exposed grant-inspection RPC.

Local Host/server issuance accepts only a `LocalPrincipalMutationActor` supplied by the authenticated local connection. Within an immediate writer transaction it checks the current Host, initialization, active principal, native identity and public verifier, compares the expected revision, then calls the canonical structural-Owner root or exact delegated issuance rule. It inserts only that returned candidate and an audit event atomically. The real issuing actor, grant ID, grantee, exact target, capability, delegation flags and source grant are recorded without native identity, verifier or secret material. The caller cannot supply GrantedBy, a preauthorized snapshot or an already constructed grant to the writer. Post-audit actor, revision and exact persisted-candidate checks plus cancellation before commit prevent stale or altered effects from escaping the transaction.

Owner-only Host/server subtree invalidation applies the foundation's exact typed descendant plan, preserving unrelated lineages and structural Owner authority. Each not-yet-invalidated row receives the same invalidation timestamp; its audit and revision changes commit with the effect. A missing root refuses. Repeating an already fully invalidated subtree at the current revision is read-only. The primitive does not invent non-Owner revocation semantics for ManagePermissions, delegation or remote actors. Post-audit Owner/revision/effect checks and cancellation roll back every effect on failure.

Schema10 adds `AuthorizationRevision` and INSERT/UPDATE/DELETE triggers on both grant tables, LocalPrincipals, TrustedManagers and HostIdentity. This covers prior enrollment/recovery/trust writers as well as this repository, including no-op updates. Revision is an optimistic token, not a grant count or a time stamp; one subtree operation may advance it several times. A missing, invalid or exhausted counter refuses a covered write. The additive migration neither creates grants nor rewrites existing policy rows. Configured default templates have their own revision coverage in schema11; see [configured defaults](v0.5-configured-defaults.md). The existing offline recovery path still owns the same exclusive lease; no client gains a database dependency.

Seven persistence scenarios cover canonical Host/server roots and delegation with actual audit provenance, exact cross-Host targets, wrong scope/issuer/source and stale native/verifier proof, typed subtree isolation, idempotent invalidation and existing principal-revocation integration, audit insertion failure and post-audit actor/grant mutation rollback, late cancellation, eight simultaneous writers with exactly one successful revision, PeerBound/Active/recovery distinctions, schema9 upgrade preservation, missing/exhausted revision state and unknown stored capability names. These are actual SQLite transaction tests with explicitly synthetic actor fixtures. They do not claim a new native authentication or management RPC qualification; prior native/service regressions remain separately required. Accessibility is waived, not passed. Physical/reboot/parity, Linux and release gates remain downstream.

[Pre-write permission denial auditing](v0.5-permission-denials.md) now commits a denial-only record for an authenticated policy refusal before any requested mutation. No requested grant/default/history/invalidation/creation effect commits on refusal. Authentication, malformed/stale/cancelled requests and later mutation/audit failures retain their separate rollback paths.
