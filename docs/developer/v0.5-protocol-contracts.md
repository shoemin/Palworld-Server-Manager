# v0.5 protocol contracts

Trial reference: #43. The normative invariant registry and accepted architecture remain authoritative.

`Contracts/Protos/host.proto` defines the initial logical handshake and bounded server inventory/identity surface plus typed grant DTOs. No listener, trust decision, permission evaluator, or business executor exists here. Later transport slices bind the same schemas for local and remote connections. Both must authenticate, negotiate, authorize, and only then dispatch. Ordinary clients continue routing remote operations through their local Host.

Contracts has only the protobuf runtime as a production package dependency. Private Grpc.Tools generates message code; `GrpcServices=None` keeps transport stub/runtime dependencies out of this assembly. The service definitions remain in the schema and descriptor for later transport-side stub generation. Package versions are pinned to Google.Protobuf 3.36.1 and Grpc.Tools 2.83.0.

Server identities always carry two nonempty UUIDs: authoritative Host and profile. `ServerRef.FromWire` rejects malformed/missing identities; use its immutable domain value for routing/maps. Generated protobuf messages remain untrusted mutable data and cannot by themselves prove valid input or authorization. Display names never determine identity. Separate Host/server capability grant messages retain their corresponding target kinds, with syntactic validation denying unknown capability values; #45 still owns every actual authority decision.

`NegotiatedProtocol` is an immutable feature intersection obtained only after explicit nonzero matching majors. Its `Require` check must run before every operational dispatch. Minor versions combine additively; unsupported capabilities are disabled. Product version text is ignored. Negotiation never grants permission. Handshake support begins with schema v1; later implementation adds concrete operation payloads within their own authorized slices rather than introducing arbitrary command or file-browser payloads here.

Trial #42d3b adds the `LocalPrincipalSecurity` feature and `Protos/local_security.proto` for the [local security RPC adapter](v0.5-local-security-rpc.md). It retains the same Contracts dependency boundary; the Host compiles its server stub separately. The `host-v1-1.pb` and `local-security-v1-1.pb` snapshots preserve this additive schema revision, while the original `host-v1.pb` remains immutable. Import names must match the corresponding reflected descriptor names. The guard checks each schema's own complete history.

`Fixtures/host-v1.pb` is a committed descriptor snapshot of the first schema. Evolution tests compare message field numbers/types/names/presence, enum values, service signatures, and preserved reservations against every committed `host-*.pb` snapshot; negative mutations prove the guard fails on breaking changes. Every schema revision requires a new snapshot matching its complete descriptor while retaining all earlier snapshots. Never regenerate old fixtures merely to pass a failing test. Removed fields reserve both name and number; removal is rejected within the same major/package even with reservations. Semantic changes also require an explicit protocol-major change under the accepted architecture. The guard checks structural compatibility; it cannot infer semantic meaning changes from unchanged source types.
