# Local peer trust inspection and revocation

The local security listener offers `LocalPeerTrustManagement` (17), introduced with protocol1.15. The current local offer1.16 adds separate [Owner replacement decisions](v0.5-local-owner-replacement-rpc.md). `ReadPeerTrust` and `RevokePeerTrust` require this explicit feature and local principal security on the same actual Windows native-identity/TLS connection. A capable older-minor client can negotiate the feature; a version string cannot enable it. Existing local and peer descriptors remain immutable; new `host-v1-15.pb` and `local-security-v1-15.pb` snapshots capture the additive wire change.

The current local Owner or a currently authorized local principal with `ManageTrustedManagers` on this exact Host can inspect or revoke peer trust. `ManagePermissions`, pairing, transport eligibility and grants on other Hosts do not substitute. The Host's owned-session permission dispatcher checks negotiation, current native-bound authentication, runtime ownership and cancellation, then invokes a synchronous fixed facade. The adapter never nests the connection dispatcher, accepts an actor/Owner assertion, or exposes arbitrary repository callbacks.

`ReadPeerTrust` returns at most16 entries ordered by canonical peer Host ID, with a keyset continuation, current authorization revision and each relationship's current incarnation. Entries contain only public identity, closed trust state, public current/pending fingerprints and recovery-required status. Pending keys are not promoted. Each page checks current permission inside the same transaction as its projection; successful reads change no authority or audit state. Denied capability use follows the existing bounded denial-audit path. Pages are observations across potentially changing state, not a frozen multi-page snapshot or an execution permit.

`RevokePeerTrust` accepts only the exact peer Host ID, expected policy revision and expected relationship incarnation. It invokes the existing canonical local revocation writer, which rechecks current authority, invalidates exact dependent grant subtrees and pending replacements, retains the revoked tombstone, and writes the actual local actor audit transactionally. Unrelated peers/grants and the Owner are preserved. A changed policy returns `Aborted`; a changed incarnation returns `FailedPrecondition`. Refresh before retrying; a fresh already-revoked request is idempotent. Missing permission returns `PermissionDenied`, while changed/absent authentication returns `Unauthenticated`. Internal errors never copy database messages or input into the reply.

The reply reports only the local commit, including its new revision/incarnation and whether anything changed. Existing preprepared reciprocal notification may run after commit; public online preparation is separate remaining work. The local command never waits for an offline peer, and no response claims reciprocal delivery or a two-Host atomic transaction. [Replacement inspection/approval](v0.5-local-owner-replacement-rpc.md) has separate Owner-only RPC qualification; recovery initiation and remote administration routing remain #28 work.

Ten qualification groups cover real local TLS/native identity, explicit feature/backport/history, exact Owner revocation and unrelated state, non-Owner permission/denial audits, changed credentials/native identity/revocation, bounded pagination/current versions, stale incarnation and malformed requests, audit rollback and bounded errors, concurrent single-winner revocation, owned runtime/HTTPS/HTTP2 gates, cancellation and escaped-facade refusal. Canonical metadata and prior peer bindings are explicit fixtures; this is not a new native PAKE or physical-machine claim.

No ordinary client gains a private Host key or direct machine-identity remote connection. Creator six/limits remain approved; accessibility is WAIVED, never PASS. No physical Palworld, Windows parity, Linux production or release acceptance is claimed.
