# Native pairing crash before PeerBound

Trial reference: #44aq, within #44. The disposable Windows service runs `WindowsPeerPrecommitCrashQualification` with two simulated Hosts, distinct fixture leases and actual protected/native credentials. Owner initialization and a one-effect activation hook remain fixtures; neither peer binding is seeded.

A child initiates actual native SPAKE2 over the production TLS/gRPC path. `VerifiedPairingBarrier` delegates every cryptographic operation to the selected guarded provider. Only after actual identity verification succeeds does it emit the public `verified-before-store` phase and the verified public credential fingerprint. It then blocks without returning the verified object to the production caller, so `PeerPairingRpcRuntime.Store` cannot run. Cancellation fails the exchange rather than releasing the barrier. No production callback, cryptographic substitute or fabricated identity is introduced. This cut point is before persistence, not a crash inside a SQLite commit.

The parent matches the public phase and verified credential to the expected Host, checks its own store is still unbound, explicitly kills that live child and awaits actual exit. It then reacquires the child lease and checks both stores: no TrustedManagers/TrustedManagerPairings row, relationship incarnation, local-binding evidence, PeerBound audit, activation effect or canonical grant. The real admission policy must reject the actual peer pin for activation, ordinary management and trust maintenance. The responder cannot have received the initiator's identity binding because the initiator sends it only after its own Store returns. Each Host is inspected under its own lease; the parent never opens a live child's database.

The old invitation is explicitly canceled and the real one-second source backoff is respected. A fresh child starts from the same protected/native identity with the barrier disabled and no peer trust. An actual activation attempt against its live peer endpoint must fail; independent admission assertions prevent treating an arbitrary network error alone as trust evidence. A fresh native invitation with a new identity must then create PeerBound independently on both Hosts, followed by normal pinned activation. After orderly exit, each Host has exactly one binding audit and one fixture activation effect, with zero canonical grants. The interrupted exchange contributes no durable binding history.

The shared private binary code handoff is unchanged. Public configuration/reports contain no code or Host private bytes. Parent code copies are disposed before termination. Child exchange/code memory is still live at the barrier and disappears with its process; this deliberately does not claim graceful zeroization in a killed process. No ephemeral PAKE state is persisted or recovered. Actual exit and whole-generation shutdown precede exact fixture native/protected cleanup, with bounded child/control lifetimes.

A requested native provider now requires separate `PrecommitCrashQualified` and `PairingCrashQualified` readiness bits, as well as the existing receipt case. Provider-less integration does not claim either native scenario. The prior post-PeerBound restart with PAKE disabled, receipt recovery and two-user/provider/native-key protections remain required. Exact results and both review passes are recorded in the experiment ledger. Ordinary self-tests do not execute this privileged service case.

This qualifies an initiator process crash after actual identity verification and before PeerBound. It does not establish the responder's asymmetric crash boundary, a mid-transaction kill, power loss/reboot, physical multi-machine LAN, installed full-network enablement or release acceptance. Accessibility remains waived for the trial.
