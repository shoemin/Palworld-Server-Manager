# Recovery retry after authenticated security contact

Trial #28s connects the fixed [sender](v0.5-recovery-completion-sender.md) and [reverse client](v0.5-recovery-completion-pull.md) to a generation-owned `PeerRecoveryContactCoordinator`. A successful native TLS and semantic Host/protocol negotiation in the existing activation, rotation status, proposal, promotion-receipt or current-credential client signals a retry. The trusted runtime checks initialized current Owner state and actual current local/peer keys before scheduling. A `PeerBound` relationship is not scheduled. The known root HTTPS address comes from that outgoing security call; incoming TCP source ports, pairing addresses and unverified discovery data cannot directly signal it.

The coordinator holds at most32 live workers, one active attempt sequence per peer and one coalesced latest-contact signal per sequence. Scheduling performs no network, persistence, cancellation callbacks or disposal inline and suppresses ambient execution context. Each sequence has one30-second deadline, including any newly signaled follow-up. It never retries itself on a timer, starts work merely because a generation starts, or persists an address/task queue. A later authenticated contact can create a fresh sequence from the original durable acknowledgment marker.

Each attempt enters the generation traffic lifetime and rechecks current keys. It tries the outgoing acknowledgment and then independently retrieves the peer's acknowledgment using fresh native transports. Failure or lack of support in one direction does not suppress the other while current keys remain valid and the overall deadline permits it. The existing clients retain their own15-second deadlines and canonical receipt/confirmation rules. `AttemptFinished` means the worker ended; it never means a matching recovery receipt was confirmed. Only canonical durable state determines that result. Recovery push/pull calls do not signal the coordinator, so they cannot recursively create more retries.

Shutdown seals scheduling, cancels and drains all actual worker tasks, including their native callbacks and transport cleanup, before disposing the generation certificate. Removed peer entries still occupy worker capacity until their actual task has completed. Cancellation callback failures do not bypass draining. No grant/default/Owner mutation, new protocol/schema/provider, ordinary client authority or operation executor is introduced.

Nine test groups exercise latest-address coalescing without inline or ambient-context work;32-worker capacity and actual cleanup drain; a single controlled deadline canceling a queued follow-up; callback failure; real native independent mutual completion without recursion; a failed push followed by a successful pull and a later new-contact retry; current key/Owner/cancellation refusal with unchanged state; generation shutdown with a held real native callback; and a genuine outgoing rotation-receipt negotiation triggering the hook only after exact semantic/capability proof. Coordinator input is an explicit trusted fixture in the native lifecycle tests; the separate hook test supplies actual native negotiation. Controlled Host-side reply faults and callbacks are not actual remote process/network fault qualification.

This integrates the existing fixed security clients. Public recovery/revoke/approval initiating commands and actual remote process/network hang/drop qualification remain parent #28 work. A denied ordinary administration request still makes no outbound contact; no retry hook is installed before an ordinary permission denial. Future ordinary business clients must preserve their originating-user and independent machine-ceiling checks. Pairing uses a separate listener and does not invent a peer-security return address. Six creator permissions and limits remain approved; accessibility/screen-reader certification is WAIVED, never PASS. No physical Palworld, Windows parity, Linux production or release acceptance is claimed.

The Astra trial used no external GitHub Codex reviewer. Astra was responsible for both implementation and technical review.
