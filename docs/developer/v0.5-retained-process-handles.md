# Retained process observation handles

`IProcessAttachment.Attach` accepts a trusted Host observation of a PalServer candidate. The Windows implementation opens only limited-query and synchronization access, compares PID, exact UTC creation time and exact image-path spelling through the opened handle, and retains that same handle only after all checks pass. Missing, changed and uncertain identities return distinct results without a lease. Failure and cancellation dispose any untransferred handle. No client-supplied PID, path normalization, process control or management permission is introduced.

The read-only lease polls native wait state before reading an exit code. Running and uncertain state remain distinct. A signaled process may expose its actual signed exit-code bits, including259 or negative values; an unavailable exit code stays null rather than becoming success. Disposal is idempotent and serialized with polling, preventing freed-handle races, and never terminates the process. The immutable identity remains available after disposal.

This pins one OS process identity, not the complete server lifetime or its descendants. The Host must still map protected paths to qualified server identities, establish ownership, track launcher/child handoffs, persist/recover operations and finish exit collection before declaring a server stopped. No new Host caller, launcher, kill action or finalized-state permission exists yet. Closing a client is unrelated to this Host-owned observation lease.

Tests cover actual synthetic Windows processes, mismatched creation time/image spelling, read-only disposal, natural exits37/259/-1, denied new process opens while a prior handle remains valid, concurrent polling/disposal, cancellation and missing/malformed identity. Process permissions are changed only on a test-owned child; cleanup uses its already held handle. These tests are not real Palworld, service launch isolation or full lifecycle parity evidence.

The native termination-code behavior and required query access are documented by Microsoft in [GetExitCodeProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getexitcodeprocess). See also [native observations](v0.5-native-process-observations.md).
