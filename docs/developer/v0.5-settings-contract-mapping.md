# Settings observation contract

Trial reference: #47. This component adds Core-independent protobuf observations and a pure Host mapper. It exposes no RPC, feature capability, file reader, revision issuer or save operation. Core and the frozen legacy application remain independent of Contracts.

The Host maps only keys present in explicitly supplied, decoded configured and installation-default inputs. Definitions come from the accepted semantic catalog. Editor kinds, sensitivity and validation codes map explicitly, with unspecified/future enum values refused. Unknown sensitivity is distinct from nonsecret. Stored passwords and unclassified values are absent from configured/default/effective observations, catalog defaults and errors; no masked placeholder can become a saved value. A protobuf diagnostic string therefore contains no such input values. Nonsecret values still must not be indiscriminately logged.

Configured and installation-default observations remain separate. An absent observation differs from an explicitly empty string. Effective is always absent from this mapper; a later authoritative observer must establish it. Existing invalid nonsecret values remain exact decoded text with a closed validation result, allowing the later editor to display a future enum choice or historical invalid text without silently normalizing it. Only explicit dirty fields may later be saved. Range, step, catalog default and restart metadata remain absent unless established by the catalog; the mapper invents none.

Every snapshot carries an exact Host-qualified ServerRef and the authoritative nonnegative int64 RevisionId as canonical invariant decimal text. The accepted store advances this monotonically; zero is its initial revision. Clients compare and return the token unchanged. Shape validation cannot prove revision provenance, freshness or authorization. The later protected route must obtain this version from the existing authoritative revision repository and enforce it on saves; never use a public hash of secret-bearing file content. Inputs and output definitions are copied. Limits are 1,024 entries, 256-character keys and 1,048,576 aggregate UTF16 code units per input collection and across output setting metadata/values. Identity and revision fields have separate fixed bounds. Unsupported or oversized observations refuse with a constant error and no inner exception. Values must contain well-formed Unicode but can fail semantic edit validation. Metadata uses tighter individual bounds. These transport limits are not game setting ranges.

Later protected routes require the approved exact-server ViewServer for nonsecret reads and EditSettings for saves independently. Both originating local-principal and receiving Host machine ceilings remain required remotely. This mapper grants neither. ViewServer reads cannot call the legacy loader that creates missing files. Actual Host inventory, fixed protected paths, stopped-state authority, revision checks, durable operation locks and atomic replacement/recovery remain outstanding. No save request or secret replacement action is introduced here.

Validation covers all editor kinds, unknown metadata, both secret fields and unclassified redaction across every source, immutable copies, distinct missing/empty/default/configured values, culture-independent interpretation, existing invalid values, malformed/unknown enums, exact identities, resource bounds, constant failures and a new immutable settings descriptor snapshot. Prior descriptor fixtures are unchanged.

The [authorized schema API](v0.5-settings-schema-api.md) now exposes catalog definitions through protected local and Host-to-Host reads. Configured-value observation routes and saves remain separate pending work; this pure mapper still performs no settings file IO or authority check itself.
