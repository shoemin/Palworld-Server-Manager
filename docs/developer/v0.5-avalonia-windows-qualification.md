# Avalonia local connection qualification

Trial reference: #52c2a. The explicit Windows integration fixture extends the [accepted local security qualification](v0.5-windows-local-security-qualification.md) with the real Avalonia client assembly. Its test executable uses `App.CreateMainWindow`, actual pointer activation of **Connect to This PC**, the production `WindowsClientSecurity` factory, installed service, pinned local IPC and each real non-admin user's CurrentUser DPAPI store. The test injects no connection result, transport, authentication or principal state. Headless windowing permits input routing in the CI user sessions; it is not a replacement for native desktop accessibility testing.

The existing protected per-user request/result directories carry only the same allowed client outputs. Success adds public semantic HostId to the principal/Owner result; the fixture checks both against the actual service and current user store. Refusal returns the fixed UI diagnosis, with no success data, rendered identity or invented inventory. Unexpected integration exceptions emit a fixed failure instead of raw detail. Each window closes in a finally block; the UI attempt has a thirty-second fixture deadline, the process helper forty-five seconds, and the existing outer cleanup removes the product service, native cache, machine artifacts, test users/profiles and copied binaries.

Required actual cases are unregistered-user refusal, proved Owner and enrolled non-Owner success, revoked-user refusal after UI-triggered service activation, explicit re-enrollment, Owner credential recovery, final authenticated dormant-service activation and old-Owner refusal. Full Host identity and unavailable-inventory presentation are checked on the actual result. Existing CLI-triggered activation cases remain separate and retained. No user/Owner enrollment is performed by the UI; the earlier explicit ceremony fixture remains the source of authorization.

Run `scripts/test-windows-integration.ps1` only in the isolated elevated Windows runner supported by that fixture. Ordinary build/self-tests and the injected Avalonia render/input suite remain separate regression checks. Actual acceptance is recorded by exact CI run and commit in the [trial ledger](../experiments/astra-v0.5.0-trial.md); code inspection or a local non-elevated run cannot count as its PASS.

Full #52 retains a **FIELD EVIDENCE REQUIRED** gate for native screen-reader/high-contrast/window-decoration qualification. The eighteen inspected actual Skia renders cover 16:9, 21:9, narrow, three palettes and enlarged text; they do not establish native assistive-technology behavior. Required field observations include announced landmarks/full Host-qualified identities, focus versus activation, hidden panels excluded from navigation, connection status/failure announcements, focus return, native window controls and high-contrast focus/selection readability. Record OS/Avalonia version, assistive tool, exact build, actions and observed results before accepting that gate. #55 and Linux/release gates remain independent and incomplete.
