# Authenticated Host permission dispatch

Trial reference: #45k. The internal LocalPermissionDispatcher and PeerPermissionDispatcher connect the existing authenticated Host connection lifecycle to canonical permission actions. Each runtime owns its dispatcher; each connection is associated with exactly the runtime that created it. A connection from another runtime refuses even when Host IDs, data or pins coincide. No wire endpoint, advertised feature, business operation or UI is added. Future RPC handlers must negotiate their own operation features. The [component acceptance inventory](v0.5-authorization-component-acceptance.md) records the qualified engine.

Dispatch requires the server's actual HTTPS/HTTP2 context and connection feature, then holds its existing Invoke lifetime gate. Local dispatch binds the native OS principal from trusted runtime composition, requires LocalPrincipalSecurity negotiation and an initialized Host, and derives proof only from GetCurrentPrincipal().MutationActor. Peer dispatch requires the established PeerTrustActivation negotiation and derives proof only from the connection's original negotiated PeerId/incarnation and actual completed-TLS pins. The [guarded observation](v0.5-bound-peer-observation.md) checks that proof atomically with any rotation observation before the permission action; existing trust-maintenance callers retain their behavior.

A synchronous trusted Host callback receives a short-lived internal facade containing no public actor, Owner flag, verifier, fingerprint, snapshot or repository. Local calls support typed capability use, direct grants, atomic presets, Owner default configuration, historical reissue and typed invalidation. Peer calls support typed use, direct grants, presets and the existing trusted confirmed-creation seam; no Owner default/reissue/revoke operation is exposed through the peer facade. Request proposals still contain only canonical typed request data. Every action feeds the captured real actor to the existing repository, which revalidates proof/policy/revision at its own transaction boundary.

The facade is disposed when the callback returns or throws. It checks owning thread, open lifetime and linked caller/request-abort cancellation on each use; escaped or foreign-thread calls cannot execute. The callback is Host implementation code, never a client-supplied delegate. It is intended for one canonical action or an atomic preset, not a transaction spanning arbitrary multiple calls or a long-running operation identity. A returned use revision remains an observation, never an execution permit. Future Host operation writers must reauthorize at commit.

Credential observation and permission mutation are separate local transactions. A valid actual Pending-key presentation may promote that key before a later permission request is stale or denied; the promotion never manufactures a grant. A stale permission revision must be refreshed. Independent initiating-local-user and remote-machine ceilings remain mandatory; the creator's exact six use-only grants do not authorize every local user. Creator callbacks remain trusted database-only confirmation of already successful creation, never a wire success flag or actual Palworld executor.

Six scenarios use real production client P256 signatures and the real Host verifier with explicitly controlled native/HTTP/TLS/session fixtures. They cover all local and peer facade action families, actual issuer/provenance/denial identity, Owner boundaries, exact six creator grants and independent local-user denial, missing/wrong channel/negotiation/current key/native/pin/incarnation/recovery/initialization, cross-runtime contexts sharing the same data, cancellation/request abort, disposal/escaped/foreign-thread calls, and valid rotation observation followed by stale/denied permission with no grant effect. These are adapter tests, not new permission-RPC transport or multi-machine acceptance. Existing actual transport/native/service regressions remain required. Accessibility is waived; physical parity, Palworld, Linux and release qualification remain downstream.
