# Explicit operation definitions

Trial reference: #46a. This pure BCL domain supplies the fixed architecture9/10 target, exclusion and per-kind recovery declarations. It is the first bounded unit of #46, not the durable execution framework or component acceptance.

OperationTarget is HostTarget or ServerTarget carrying the full existing domain ServerRef. OperationLockScope independently represents HostScope or ServerScope. Each trusted operation definition explicitly chooses None, ServerExclusive or HostExclusive; a server-targeted operation can require HostExclusive. Host targets cannot request ServerExclusive. The pure destination check refuses a foreign authoritative Host. It does not authenticate a caller, acquire a lock or grant permission.

HostScope conflicts with every scope on that Host. ServerScope conflicts with its HostScope and the exact same ServerRef only. Equal profile IDs on different Hosts do not collide. No shared/read/write modes, path-string locks, expiry or automatic release is introduced.

Trusted executor code supplies bounded case-sensitive kind/phase names, a nonterminal initial phase, every allowed transition and an explicit recovery disposition for every nonterminal phase. Terminal phases have no successors or recovery disposition. Unknown names, enum values, dangling transitions and phase sets without a declared route to terminal resolution refuse. Explicit retry loops with a resolution path are valid. Collections are immutable copies. There is no default recovery classification, generic resume action, concrete backup/update/transfer phase policy, client-defined operation registration or executable callback in these types.

Four pure scenarios verify the independent target/scope mapping, the complete36-entry symmetric conflict matrix, equal-profile Host collisions and authoritative-destination checks, closed identities/enums, all four recovery dispositions across separately declared kinds, terminal/unknown/forbidden transitions, caller collection mutation and invalid/unresolvable definitions. These tests establish definition behavior; they do not prove database exclusion, crash recovery, connection lifetime or multi-client Activity visibility.

Subsequent #46 units must use Host-owned transactions for stale-resource writes and atomic operation-record/lock acquisition and terminal release. Actual execution and recovery belong to the Host operation identity, never a client connection; interruption classification comes from the concrete trusted executor, with ambiguous work shown as Recovery Required. Client status Contracts and startup integration remain pending. Authorization must still be checked at the actual mutation boundary; these declarations create no authority or offline command queue.

Accessibility certification is WAIVED, never PASS. Physical Windows parity, Palworld, Linux and release gates remain downstream. The Astra trial used no external GitHub Codex reviewer. Astra was responsible for both implementation and technical review.
