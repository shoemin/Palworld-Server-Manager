# Recoverable routine rotation material

Trial reference: #44j, within #44. This unit composes the [durable Prepared reservation](v0.5-rotation-preparation.md) with protected Windows credential generation and recovery. It does not start staging, publish a descriptor, change Current, propose a peer pin, cut over a listener or retire an active key. Installed service and local Owner RPC composition remain later work.

The trusted Host owns one `RoutineRotationMaterialCoordinator` under its machine lease. Its gate serializes concurrent preparation requests. The composition owner must quiesce this work before running credential reconciliation/deletion; a machine lease alone does not serialize two operations within the same process. The caller supplies a principal actor produced by actual local authentication, not a client-claimed Owner identity. Persistence rechecks that exact active Owner/native/verifier tuple both when reserving the rotation and when recording the validated fingerprint.

`IHostRotationMaterial` exchanges only Host UUID, an opaque reserved reference and public fingerprint metadata. `WindowsHostCredentialMaterial` owns all protected PFX retrieval, certificate loading and private-key use. An existing value must contain a currently valid P-256 certificate for the same Host UUID and a private key that proves possession against its public key. Known public metadata must match exactly. Every retrieved/exported secret buffer and temporary proof buffer is cleared on both success and failure; no secret is returned to the coordinator or persisted in ordinary SQLite.

Missing material with no recorded fingerprint can be created once under the serialized reservation. The stored result is read back and verified before its fingerprint is recorded. If storage reports failure after saving, the caller receives failure and a later deliberate retry recovers the same saved key. Missing material with a recorded fingerprint, corrupt material, wrong Host, wrong curve, missing private key, invalid validity period or mismatched public metadata fails closed without generating or overwriting a replacement. Repair/abort is explicit; this path cannot recover a compromised Current credential.

Completion updates the Prepared reference's public metadata and writes a fixed local-Owner audit event in one SQLite transaction. A changed Owner, aborted rotation, changed Current, mismatched metadata or failed audit refuses completion. Cancellation after storage can leave the reserved key without metadata; retry is safe and does not create another key. No failure handler deletes a retained key. Once the request is beyond Prepared, this coordinator only returns its durable status and does no material work; validation/publication for those later phases belongs to the complete rotation engine.

Three ordinary scenarios cover an acknowledged-lost write, a new coordinator over the same durable reservation, twelve deliberately overlapping requests behind a blocked material call, missing recorded material, cancellation, audit rollback, Owner credential change during validation, concurrent abort, invalid existing certificates, private-buffer clearing and unchanged Current/peer/grant state. The privileged Windows service fixture also creates, reloads and validates a reserved credential using the actual service account's DPAPI/ACL protected store. That is protected-store reload evidence, not a process-kill, reboot, global cutover or multi-machine field result. Full #44 remains incomplete.
