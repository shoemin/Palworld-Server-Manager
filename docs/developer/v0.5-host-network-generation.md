# Owned Host network generation

Trial reference: #44v, within #44. `HostNetworkGeneration` owns one loaded Host TLS certificate, the [shared traffic lifetime](v0.5-host-traffic-lifetime.md), its listener applications and pairing runtime. The Windows composition root provides a local-only factory and an explicit full-network factory. Both take ownership of the supplied certificate, including startup failure. The full factory verifies initialized Host identity and the actual current public fingerprint, requires a concrete activation hook, and binds local, pinned-peer and first-contact pairing listeners to the same pre-TLS lifetime. The installed service continues to use the local-only factory; no remote endpoint or local rotation RPC is enabled here.

Every exposed outgoing pairing, activation, status, proposal, receipt and acceptance-collection helper runs inside a whole-operation scope, including post-reply persistence, audit and transport disposal. Invitation creation/cancellation and other trusted Host work use the same admission gate. These internal methods do not authorize a caller: the future locally authenticated action still needs its fresh Owner/capability checks. The #45 activation hook remains mandatory and has no production no-op fallback.

Stopping seals configuration and admission, cancels startup and active work, and waits for any in-progress startup to exit. All constructed listeners are asked to stop before awaiting the complete traffic drain. It then awaits every listener stop/disposal, disposes the pairing runtime and its background audit/attempt maintenance, disposes the traffic lifetime, and finally releases the certificate handle. A failure remains a failure while the remaining cleanup steps are attempted. Repeated/concurrent stops share the same completion. Protected secrets and native cache containers are not deleted: retirement remains a separate policy.

Only a successfully stopped full-network generation can supply its cached cutover coordinator, bound to its own credential repository and acceptance collector. A partial stop, timeout, failed audit flush or cancellation callback cannot supply it. This proves closure of that generation only: the machine-lease holder must keep other listeners/mutations quiesced and must not start a replacement generation before the final eligibility transaction/publication succeeds or authoritative recovery is complete. The generation never starts a replacement itself. The existing cutover coordinator still freshly validates Owner, proposal, every current peer and remaining acceptance time. A stored public snapshot or historical acknowledgement cannot bypass it.

Seven initial ordinary scenarios exercise actual local/peer/pairing traffic ownership, all closed outgoing helpers, in-flight work, partial listener startup/precancellation/wrong-key cleanup, audit cleanup failure, stop during actual startup, callback failure and owned shutdown followed by the real cutover transaction, New local TLS and actual peer promotion receipt. Authority and material/publication boundaries remain explicit fixtures in this handoff scenario; separate Windows service qualification supplies actual protected material/publication evidence. The pairing provider in these ownership tests deliberately refuses proof; native PAKE success remains qualified separately.

An eighth regression injects failure creating the pairing attempt timer after the audit timer exists. It failed against the previously accepted runtime constructor because the audit timer survived the failed construction. The constructor now disposes any previously created audit writer and admission semaphore before rethrowing, preserving a cleanup failure as well when necessary. This corrects an earlier PR98 lifecycle escape; the generation cannot dispose an object whose constructor never returned.

Complete Host-wide rotation action scheduling, installed initiation/configuration, retirement and full crash/physical qualification remain outstanding.
