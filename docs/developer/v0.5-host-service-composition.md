# Windows Host service composition

Trial #42d3c1 wires the shipped Host executable to the local security RPC listener. The fixed Windows composition selects `PalworldServerManagerHost`, its virtual service identity, the protected product Host/PublicTrust directories, the global Host lease and pipe `PalworldServerManager.Host`. Installation and offline machine bootstrap must already have prepared the protected directories, authoritative credential and native key creation permission. Service startup never grants permissions or replaces missing credentials.

The elevated installer creates missing parent folders separately: Administrators own them, only Administrators/SYSTEM may replace their children, and ordinary users have public traversal. The service's full directory access begins at Host, never at the common parent containing Owner handoffs. Existing unsafe parents are refused, not repaired. This corrects an earlier default-layout defect in which the recursive directory creation API spread the Host ACL into missing parents.

The SCM start callback launches an independent worker and returns promptly. The worker holds the machine lease throughout root/ancestor/child ACL and reparse validation, migration, semantic identity loading, authoritative trust publication and stale-key retirement, Current private-key/fingerprint validation, native cache loading and the listener lifetime. Native CNG work cannot block the SCM callback. A startup failure or unexpected listener termination cleans up and exits the process with failure, leaving no apparently running Host. Ordinary shutdown cancels and drains the listener; application and certificate disposal precede lease release. A crash abandons the OS lease; the next process performs reconciliation before opening IPC.

The production application uses an empty ASP.NET Core builder with an explicit Production environment. No appsettings, environment URL, hosting-startup assembly or command-line endpoint configuration is loaded. Only the TLS named pipe is configured. gRPC messages are bounded to 16 KiB, detailed errors are disabled and request/exception logging providers are absent. The existing per-connection negotiation, native caller identity and principal/ticket authorization apply to every security RPC. Before initialization the only authority effect remains intended-user bootstrap completion.

Ordinary tests exercise the same listener builder under hostile hosting environment settings, all adapter security tests, and worker cancellation/failure cleanup. The explicit Windows integration adds the shipped Host and Host.Cli executable fixture on disposable GitHub runners, refusing pre-existing product service/group/data/native permissions and cleaning only its own resources. It checks independent startup, publication reconciliation, uninitialized refusal, service restart/crash, machine-lock ownership, absence of TCP, unchanged activation ACL, missing authoritative private material despite a surviving native cache and explicit offline recovery. The [ordinary-client composition](v0.5-client-security-composition.md) is implemented; final actual two-user Owner ceremonies remain #42d3c3; full #42 is not yet complete.
