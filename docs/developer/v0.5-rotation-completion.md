# Rotation completion and quiesced retirement

Trial reference: #44an, within #44. Completion is distinct from cutover. The final gate reads every current nonrevoked relationship inside the authoritative writer transaction. Each must be Active, outside recovery, have a valid current pin and positive current incarnation, and have either a matching rotation promotion receipt, an explicit current-credential confirmation, or first-binding proof for the actual local New credential. Historical timestamps and expired deadlines never substitute for evidence. An offline unresolved peer retains Old indefinitely; revocation resolves that peer without contact. PeerBound remains conservatively unresolved until activation or pending-trust cleanup.

The first-binding alternative recognizes a peer paired under New without inventing a promotion event. Every evidence alternative must match the current incarnation. Recovery reversal, unproved key replacement or pairing metadata changes invalidate stale evidence even if identity/key values return to their earlier state. The receiver's local promotion alone is insufficient: its receipt must reach durable Host storage, or an explicit current-key confirmation must commit. No online contact is needed again for a still-current first-New binding after activation.

Inspection authenticates the exact current local Owner and actual generation credential, and requires an exact CutOver/Completed rotation whose New is still authoritative Current. It is advisory until the final writer. Completion obtains an immediate transaction, repeats those guards and all peer predicates, then changes State to Completed and records its Owner audit together. After audit work it checks exact rotation identity/credential references, Owner, peer revision and every peer predicate again, plus cancellation. Changed authority, new membership, stale evidence, audit failure or cancellation rolls back the transition. A Completed retry is read-only with fresh Owner/current-New scope; it preserves its original completion event rather than reopening history for later relationships.

The Host transition checks eligibility before disrupting service. It then closes the entire current New generation, including incoming connections, outgoing transports/callbacks, discovery, pairing attempts/audit timers and borrowed credential handles. Only a successfully stopped generation provides its cached completion coordinator, bound to its own repository and actual credential. The composition retains the machine lease and excludes other writers throughout. A trusted persistence seam cannot be treated as an ordinary online action; there is no new incoming local RPC that could deadlock waiting for itself to drain.

After the commit, existing trust reconciliation runs while still quiesced: publish authoritative New, reconcile native cache retention, delete eligible protected secrets, then record retirement metadata after actual deletion. Successful reconciliation is followed by a fresh generation using the already reconciled Current. Failure before or during this reconciliation leaves the transition Quiesced for explicit authoritative recovery. Before commit, Old is still retained; after commit, recovery resumes eligible retirement from durable Completed/Current New. Failed generation drain, replacement startup or the existing explicit-recovery reconciliation failure remains Faulted under the established lifecycle contract. A timeout or failed cleanup never supplies quiescence.

Five persistence scenarios cover offline/expired/unacknowledged peers, revoked resolution, each evidence alternative, stale and missing incarnations, first-New activation, legacy evidence gaps, exact scope, queued Owner/relationship/cancellation changes, audit/post-audit rollback and idempotence. Three new generation scenarios cover non-disruptive refusal, post-commit reconciliation failure/recovery, final authority checks during slow shutdown and failed audit cleanup. The three-Host scenario resolves one peer while the other has not contacted New, advances that receiving peer's own deadline through its actual lapse writer, then verifies that local promotion over real New TLS still cannot permit completion until the receipt commits. Existing actual TLS/cutover/receipt and discovery tests now complete the rotation and start a fresh New generation.

The disposable Windows service qualification additionally checks actual encrypted Old file and native container retention before completion, a failed New publication after durable completion with listeners demonstrably closed, and explicit recovery that removes Old while retaining the original usable New protected/native material. It verifies current local TLS after restart and one completion audit with zero grants. These exact fixture checks do not establish physical-LAN, process-kill/reboot or installed-product configuration acceptance. No new schema/protocol, revocation engine, capability defaults or release enablement is included.

A separate [receiving-peer process recovery qualification](v0.5-peer-receipt-process-recovery.md) checks that completion refuses a promoted but undelivered receipt and succeeds after a new receiver process delivers the retained ID through ordinary authenticated RPC. Its actual process termination is separate from the publication-fault/object-recovery cases above.
