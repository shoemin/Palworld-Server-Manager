# Authorized settings schema reads

Trial reference: #47. `GetSettingsSchema` returns the Core catalog's 95 known setting definitions for an existing exact Host-qualified server. It reads registration from the authoritative inventory but never opens an installation or settings file. Inclusion in this catalog is not a claim that a setting exists in that installation. Discovered keys carry definitions in configured settings snapshots.

The protected local RPC requires a current authenticated local principal and exact-server `ViewServer`. `EditSettings` alone does not authorize a read. The Host rechecks permission before returning metadata. Catalog defaults are withheld for secret and unclassified sensitivity; stored/default-file/effective values are never part of this reply. Numeric bounds and restart behavior remain absent where the catalog has no established evidence. `SupportsSemanticEdit` describes an editor kind, not the caller's permission to save.

`GetRemoteSettingsSchema` routes through the originating Host's generation-owned, pinned peer transport. The local principal needs `ViewServer` for that exact remote server before any outbound contact, again before dispatch and before receiving the result. The destination separately checks the originating machine's exact-server `ViewServer` ceiling and current Active relationship. Negotiation alone, pairing, an EditSettings grant or a creator's machine grant never authorizes every local user. Ordinary clients never hold Host credentials or contact a peer directly.

`SettingsSchema` and `LocalRemoteSettingsSchema` are explicit negotiated features; the latter is offered only with a configured peer generation. They do not advertise value reads or saves. Requests and replies use canonical nonempty qualified identities. Replies are bounded by the existing 16 KiB message limit and validated for exact target, unique keys, closed kinds/sensitivity, metadata shape and secret-default withholding. Errors are constant and never echo arbitrary peer or native messages. The schema has no configuration revision: it exposes catalog metadata, not an editable file snapshot.

Actual authenticated local/TLS peer tests cover independent grants, Owner reads, missing/foreign targets, revoked grants and credentials, missing feature negotiation, non-Active trust, denial before outbound contact, revocation during negotiation and withholding a reply after a local credential change. Immutable protobuf history snapshots are additive. No settings file is created by these reads.

This component completes only the schema endpoint. The [configured settings API](v0.5-configured-settings-api.md) separately supplies protected value reads and durable content revisions. Independent EditSettings saves, stopped/finalized state, durable operation ownership and atomic save/recovery remain required for #47. No game lifecycle, UI, Linux, permission defaults or creator rights change here.
