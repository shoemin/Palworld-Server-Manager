# Native simultaneous own-key recovery qualification

Trial #28p starts with two genuinely paired and explicitly activated Hosts using actual protected local Owner RPCs and canonical configured-default hooks. It fully stops both old network generations and verifies that their certificate handles are released before either canonical offline credential replacement. Each fixture keeps its exclusive Host lease. New real P256 key pairs supply the new public metadata and listeners; private material is explicitly a certificate fixture, not new CNG/DPAPI or offline CLI qualification.

Both recovered Hosts retain their semantic Host IDs, local user credentials, current local Owners and independently required recovery flags. Their new generations and local clients use the new current certificate fingerprints. Ordinary activation and old-source capability use refuse. Fresh invitations and genuine native PAKE create replacement candidates for both actual new peer keys. The test never inserts a verified candidate directly.

Each Owner separately approves its own exact candidate through the canonical command with independently signed local proof fixtures. These commands are not claimed to be public approval RPCs. The first approval clears neither recovery flag, and the other Host has not yet approved the sender's actual new key, so an attempted completion refuses without recording a receipt or confirmation. After the second approval both flags still remain set. An actual attempted connection using a retained old private key also refuses; the existing current-key check may reject it in the completed client TLS callback before a receipt reaches the peer.

The first successful current-key acknowledgment clears only its receiving Host's recovery flag. That Host advances its relationship incarnation while carrying its original outgoing approval. Its return acknowledgment then uses the new incarnation and original approval, clearing the other Host's flag. Both original markers survive with matching current incarnations, one approval/receipt/confirmation audit each and no extra Owner approval. Actual activation and canonical permission use succeed with new keys/current incarnations; old proofs and old grant roots remain invalid. Fresh roots belong to the same current local Owners. A repeated completion is read only with no pending work.

The native scenario runs with the hash-checked Windows Rust SPAKE2 provider alongside the existing native qualification. Ordinary self-tests remain634 and native scenarios are reported separately. The test fixture now accepts an optional presented certificate and pins its local trust reader to that certificate; existing tests retain their original default. Reverse disposal order guarantees that both new generations stop before the fixture's new certificates are disposed, even on a test failure. Pairing/activation are actual local RPCs; approval remains a canonical command using a separately signature-authenticated fixture.

This complements [same-key revoked re-pair](v0.5-native-repair.md) and [generation-owned completion](v0.5-recovery-generation.md). Public initiating commands, opportunistic authenticated-contact retry and actual remote process/network hang/drop remain parent #28 requirements. No physical Palworld, Windows parity, Linux or release qualification is claimed. Creator permissions and limits remain unchanged; accessibility/screen-reader certification remains WAIVED, never PASS.

The Astra trial used no external GitHub Codex reviewer. Astra was responsible for both implementation and technical review.
