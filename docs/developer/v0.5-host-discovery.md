# Pairing addresses and unverified discovery

Trial reference: #44z, within #44. The shared `HostReachableAddress` parser accepts a hostname, IPv4 address or unscoped IPv6 literal and a separate port from 1 through 65535. It produces a root HTTPS URI with no user information, path, query or fragment. Internationalized names are normalized to ASCII, IP literals to their canonical representation, and IPv4-mapped IPv6 to IPv4. Unspecified, multicast and broadcast destinations are rejected, including after normalization. Scoped IPv6 requires later platform/interface handling. Parsing validates the address shape, not reachability or trust; an actual connection can still fail.

The separate `host_discovery.proto` schema carries an explicit discovery marker, claimed HostId, protocol major/minor, and peer/pairing ports. The bounded decoder rejects malformed packets, missing identities, invalid ports and packets over 512 bytes. A future protocol major remains unverified display metadata; only the actual connection's version/capability negotiation determines whether pairing can run. The packet has no destination URL, secret, code, credential, grant or trusted identity. It does not negotiate a feature or implement an RPC. Immutable descriptor history covers this new schema without changing earlier histories.

`HostDiscoveryDirectory` is an internal Host cache, separate from legacy `Lan` and authoritative persistence. Trusted transport composition must first enforce its LAN policy and supply the actual received source address. The cache derives candidate HTTPS addresses from that source and the bounded advertised ports. It cannot infer a physical LAN from an address, classify an interface, open a socket, resolve a name, or update trusted peer state.

Each claimed HostId/source/port pair is a distinct **unverified** choice. Conflicting claims coexist instead of overwriting a trusted route or collapsing different addresses into one identity. IPv4-mapped sources normalize to the same entry. At most 256 entries remain resident; a full cache refuses new entries without evicting unexpired ones. Existing entries can refresh. Entries expire after twelve seconds of monotonic elapsed time, including during reads; wall-clock changes do not extend them. Returned snapshots contain immutable values, and restarting discards all discovery state.

A discovered or manually entered address supplies reachability only. [Address/code pairing](v0.5-peer-pairing.md) must still prove the code-confirmed Host identity against the actual TLS peer before storing zero-authority PeerBound. Advertised HostId, version and ports cannot authenticate a peer, promote trust, select a grant or authorize a local user.

Three ordinary scenarios cover manual address injection/normalization, packet/schema compatibility and limits, conflicting actual sources, bounded residency, concurrent refresh and monotonic expiry. Native first-contact qualification now constructs its endpoint through the manual parser before performing the genuine PAKE/TLS exchange. No broadcast, physical-LAN, VPN filtering or multi-machine runtime evidence is claimed by these tests.

The next Windows discovery transport must explicitly select eligible physical LAN interfaces, constrain sources to those links, own socket shutdown and retain these bounds. Automatic discovery on VPN or other non-LAN routes is prohibited; those addresses remain manually entered. Local authorization, installed remote enablement, authoritative route persistence, rotation retirement and full crash/physical qualification remain outstanding. The canonical Active default hook stays mandatory and separate.
