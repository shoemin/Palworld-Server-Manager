# Discovery within a Host generation

Trial reference: #44af, within #44. The internal full-network factory can compose an owned discovery runtime with the existing local, peer and pairing listeners. Installed startup remains local-only. The factory seam is trusted Host composition, with no ordinary-client or RPC-selected implementation and no production no-op activation hook. Concrete installed port/bind policy remains separate.

Peer endpoint configuration is sealed before startup. Its reader runs after every listener starts, replacing post-start endpoint mutation. The generation validates root HTTPS endpoints, then builds public metadata from the configured stable HostId, the operational pairing Hello protocol, and the actual bound peer/pairing ports. Ephemeral listener ports are resolved before advertisement. The discovery runtime returned by the factory transfers to the generation before any cancellation or ready check; a cancellation race cannot strand it. A factory that throws still owns cleanup of anything it did not return.

The generation becomes ready only after configured discovery startup. Clean temporary native outages remain inside the runtime's bounded retries, so the local channel and manual pairing service can stay available while discovery has no hints. Unexpected discovery Completion, including an unexpected successful end, is a generation fault: the owner closes admission, signals listener failure and initiates shutdown. The original cause remains in terminal cleanup results; a successful unexpected end is also recorded as failure.

Stopping closes generation admission, cancels startup/traffic and awaits startup ownership transfer. It initiates discovery disposal and every listener stop before awaiting complete traffic drain. It then awaits discovery's whole receiver/send/cancellation lifetime, all listener stops/disposals, pairing maintenance and certificate cleanup. Discovery's observer never awaits the stop that observes it. Failed discovery cleanup, timeout or partial shutdown cannot supply the successfully quiesced cutover coordinator. Protected/native keys are still retained until a separate retirement policy permits deletion.

`DiscoverAsync` on the generation and transition coordinator is a named internal helper inside existing admission/serialization. It returns only the bounded, source-derived unverified directory snapshot; it cannot grant identity, pairing trust, authority or local-user permission. Disabled discovery and closing generations refuse the query. The later authenticated local action must still authorize its caller.

Five new generation scenarios and one transition scenario qualify actual listening ports and operational metadata, real local TLS negotiation during a synthetic outage, closed configuration, startup failure/cancellation ownership, stop-before-traffic-drain, blocked sends/receiver cleanup, fatal/cleanup failures, and a real credential cutover that waits for the old discovery send before starting a fresh runtime with an empty cache. Exclusive TCP rebinding and FirstPipeInstance supply closure evidence. The transition uses explicit material/publication fixtures and actual New local TLS; existing Windows service qualification supplies protected material evidence. Discovery transports here are internal controlled fixtures and send no physical broadcast. These tests do not certify physical adapter changes, multiple-machine discovery or a real process crash.

Concrete Windows discovery enablement/configuration, local initiation/authorization, safe retirement and complete crash/physical qualification remain outstanding. No installed remote port, new wire RPC, client UI, Linux implementation or release action is introduced.
