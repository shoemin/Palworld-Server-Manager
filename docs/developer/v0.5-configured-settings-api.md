# Configured settings read API

The Host exposes `LocalSettingsProtocol.GetServerSettings` and `GetRemoteServerSettings` on its existing authenticated local endpoint. Incoming Host peers use `PeerSettingsProtocol.GetServerSettings` on the existing mutual-TLS endpoint. Neither service is mapped to first-contact pairing. Negotiate on the security service of the same connection before these calls.

Local protocol minor20 and peer minor17 add explicit `SettingsSnapshot` capability25; local remote forwarding additionally requires `LocalRemoteSettingsSnapshot`26. A reader-less runtime does not advertise direct reads; forwarding is advertised only with a configured network generation. Existing peers remain additive-compatible, but a caller must negotiate the new feature before use. Immutable host-v1-21 and settings-read-v1 descriptors retain all previous histories.

Every request supplies an exact qualified ServerRef. Local ViewServer permission permits read-only access; EditSettings alone does not. Incoming peer requests need an Active, non-recovery relationship, current TLS/incarnation proof and exact ViewServer machine ceiling. Originating local requests also require their current local principal's ViewServer permission on the remote server before contact and before/after the remote read. Authentication, transport eligibility and pairing alone confer no server access.

The installed local Host binds one SettingsSnapshotReader for its lifetime. Full-network transition composition shares one reader across local/peer listeners and successive credential generations. The trusted direct-generation seam can omit a reader and then denies direct reads. Constructing the fixed Windows managed-storage adapter performs no IO, provisioning or repair; absent game storage cannot prevent unrelated credential/bootstrap management. No RPC accepts a file path.

The reader reuses registered managed-file binding, positive nonsecret classification, bounded parser/mapping, ordered content observations and final same-transaction permission/inventory checks. Secret and unknown-sensitivity values are withheld, including defaults. Effective values are absent without an authoritative observer. Successful reads carry a positive canonical decimal durable revision for active-file bytes; unchanged observations retain it. Defaults remain separately observed and are not covered by that active-file revision.

Read requests retain16KiB limits. Only the dedicated settings services have a4MiB response allowance; existing security services retain16KiB send/receive bounds. Semantic validation caps1024 distinct keys and1,048,576 aggregate UTF16 characters. The Host and outbound peer client additionally check serialized size, exact requested ServerRef and positive canonical revision. Forwarding uses one fresh authenticated peer connection with a15-second deadline and current-proof rechecks; generation shutdown cancels/drains it. Error details are fixed, never source exception text.

Qualification uses real authenticated local and peer transports with synthetic configured sources, large Unicode responses, independent local/peer ceilings, stale/revoked proof, sanitized failures and shutdown cancellation. Native managed-file/SCM protection is separately qualified by the existing service suite. This does not implement SaveSettings, stopped-state proof, durable file replacement, UI controls, real Palworld qualification, Windows feature parity, Linux or release qualification. Accessibility remains WAIVED.
