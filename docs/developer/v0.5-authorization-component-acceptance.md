Trial reference: #45m, completing the isolated #45 engine audit after the [successful-audit correction](v0.5-successful-permission-audit.md). The [trial ledger](../experiments/astra-v0.5.0-trial.md) records both reviews, exact commits and acceptance. This inventory does not close the canonical issue or change its Project state.

The component provides typed canonical grant rules, transactional issuance/invalidation, configured Active-time defaults, atomic presets, Owner historical reissue, approved creator confirmation, independent local/remote use evaluation, and internal dispatch from established authenticated Host connections. These are the current #45 issue's authorization-engine boundaries; concrete server operations, permission UI and unpair transport are excluded by that contract.

## Approved creator policy

Successful new remote creation grants exactly ViewServer, StartStopRestart, EditSettings, ManageBackups, TransferExport and DeleteServer on that new ServerRef. ManageServerSharing and both delegation flags are excluded. The actual creator needs CreateServer on the receiving Host; current-Owner canonical roots provide the six server permissions without converting a Host grant into server provenance. The trusted confirmation callback persists already successful creation in the same transaction; it is not a request success flag or a Palworld executor. Failed creation, existing inventory/history, wrong peer/target/proof/revision or missing confirmation gives no new grant. Each originating local user separately needs local permission.

## Qualification and limits

The accepted engine through #45l adds75 ordinary scenarios to the #44 checkpoint (403 to478), including exhaustive pure rights/type/scope combinations, actual SQLite migrations/transactions/concurrency/faults, and signed local adapter qualification. The same final executable passed the full local and remote478/478 suite, zero-warning build, actual Avalonia UI, Windows SDK ABI, native SPAKE2/transport regressions and privileged Windows service/multi-user/process-restart tests. The new permission adapters use explicitly controlled native/HTTP/TLS metadata; that is not a claim of a newly exposed permission RPC or separate physical PCs.

Whole-component review discovered a real audit-integrity gap that earlier reviews and tests missed. The original failing reproduction, origin PR137, correction PR147 and seventh accepted escape remain recorded. A passing insert or a passing earlier suite is not retroactively relabelled as proof of the newly tested integrity property.

Concrete operation writers must reauthorize at their actual mutation boundary; a returned permission revision is an observation, never a reusable execution permit. Outbound business routing must preserve both independent ceilings. Full credential-replacement/unpair lifecycle remains #28/later integration; the canonical historical grant action does not itself replace credentials or prove replacement. Actual server creation, Activity/operation framework and permission UI remain downstream. No new API capability was invented to finish this engine criterion.

The Windows parity gate #55 and broader #23 validation retain their own actual integration/field requirements. Physical multi-machine/reboot/Palworld evidence is not manufactured here. Linux remains gated on Windows parity; release publication remains outside this experiment. Accessibility certification is WAIVED, never PASS. The Astra trial used no external GitHub Codex reviewer.
