# Recovery process fault qualification

The Windows service harness requires five separate child-process recovery cases before its readiness gate can pass. Each case owns two disposable Host identities, protected credential stores, native non-exportable keys and exclusive leases. Historical verified bindings and current Owner proof are explicit fixture inputs; genuine native PAKE is qualified separately.

| Receiving child fault | Durable state and retry requirement |
| --- | --- |
| Killed before receiving completion | No receipt or confirmation; retry the original approval after restart. |
| Killed after receipt commit, with response withheld | Receipt and receiving recovery-clear survive; sender still has its original unconfirmed obligation. Retry creates no duplicate receipt audit. |
| Killed before offer confirmation | Pulling Host retains its receipt; offering Host retains its original unconfirmed obligation. Retry confirms that obligation once. |
| Killed after offer confirmation, with response withheld | Offering confirmation survives even though the caller failed. Retry reports NoPending, without fabricating a new confirmation. |
| Receiving RPC hangs in a live child | Actual client reaches its shared fifteen-second deadline. Child remains alive with no receipt; terminate, restart and retry the original approval. |

The parent observes a fixed public barrier and proves its actual client task is still incomplete before killing the owned process. Post-commit barriers use a fixed-size response buffer. The framework stream adapter was checked against [ASP.NET Core 8 source](https://raw.githubusercontent.com/dotnet/aspnetcore/v8.0.0/src/Http/Http/src/StreamResponseBodyFeature.cs); runtime pending-task and durable-state assertions remain mandatory. A process pause by itself is not evidence of withheld response bytes.

The parent accesses the child's authoritative database only after observing process exit and acquiring its released lease. Restart must preserve the real native key name and public pin, while reporting a new process instance. Exact original approval IDs, independent recovery flags, receipt IDs and one audit per effect are checked. No grant is created. Normal existing process commands and PAKE fault fixtures retain their separate branches.

The child accepts only its fixed bounded public state probe in recovery mode. Its fifty-five-second watchdog remains. Each parent case has a forty-five-second bound; the service test readiness bound is extended to 120 seconds for the added cases. This changes no production startup deadline. Generations and children must drain before native key, protected reference and exact disposable directory cleanup.

Run the service integration in the existing disposable privileged Windows CI environment. The optional self-test `--recovery-process-probe <protected-root>` requires an elevated disposable Windows harness and a correctly protected ancestor chain. Ordinary local builds and the 661-test suite do not certify these privileged process cases. Exact run outcomes belong in the trial ledger; this page describes the required checks, not a pending run's result.

Public initiating commands remain parent #28 work. These are real Windows process and loopback transport faults; they do not establish power-loss durability, physical multi-PC networking, actual Palworld operation, Windows parity, Linux production or release acceptance. Six creator permissions and their limits remain approved. Accessibility/screen-reader certification remains WAIVED, never PASS.

The Astra trial used no external GitHub Codex reviewer. Astra was responsible for both implementation and technical review.
