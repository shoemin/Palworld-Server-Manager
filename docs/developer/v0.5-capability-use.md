# Current authenticated capability use

Trial reference: #45i. Four typed Host-only repository methods evaluate local/remote Host and server capabilities from trusted current identity evidence. They add no RPC, operation executor, UI or credential holder. The [authenticated Host dispatcher](v0.5-authenticated-permission-dispatch.md) connects these checks to the existing connection lifecycle; the [component acceptance inventory](v0.5-authorization-component-acceptance.md) records the qualified engine.

Each check validates a known capability/exact target, opens an immediate transaction, rebuilds current policy and revalidates actual local or peer proof. It calls the canonical CanUse predicate. Incoming peers may target only this Host/full local ServerRef. Local outbound use additionally requires an Active, non-recovery destination even for the local Owner. The remote Host must independently authorize the originating machine; a machine grant never authorizes an ordinary local user automatically. There is no transaction spanning both Hosts.

An authenticated policy refusal uses the existing [denial-only audit](v0.5-permission-denials.md) with controlled UseHostCapability/UseServerCapability, actual actor and exact target/capability. Exact audit/current proof/revision/cancellation checks guard its commit. Malformed input, bad authentication and cancellation remain separate. Success rechecks identity/revision and cancellation and returns the current revision without creating a grant, permission change or fictitious operation audit. This return is an observation only, never a reusable execution permit. Future operation writers must revalidate identity and authority inside their own mutation boundary; a prior read does not close the check-to-use race for later business operations.

Six actual SQLite scenarios test every accepted Host/server capability against every other capability for local and peer actors; structural Owner behavior; Host-qualified collisions, grant ancestry and revocation after an earlier allowed observation; all four combinations of independent local/remote ceilings for Host and server targets; inactive/recovery destinations even for Owner; closed inputs and current keys/pins/incarnation/Active state; eight concurrent denials with exact actor/action/target and no effects; failing/deleted/mutated audit, late identity/Owner/incarnation changes and cancellation rollback. The unchanged pure-logic composition and mutation/default/preset/history/creator regression suites remain required. These controlled evidence fixtures do not prove an installed permission RPC, actual Palworld execution, physical parity or release readiness. Accessibility is waived; Linux remains gated.

[Original-connection peer observation](v0.5-bound-peer-observation.md) supplies the guarded rotation observation used by [authenticated Host dispatch](v0.5-authenticated-permission-dispatch.md). Capability-use evaluation remains separate and rechecks current proof/policy.
