# Preserved settings document

Trial reference: #47. `PreservedPalworldConfigDocument` is an additive Core in-memory model that composes the existing project-owned `PalworldConfigParser`. The legacy parser, its model and frozen WPF callers are unchanged. The new model retains original text and value spans, cross-checking every entry against the existing parser before accepting it.

An empty edit returns the original document. An explicit replacement changes only its value span; explicit additions insert inside the existing outer tuple. Unknown keys, unknown enum/compound values, comments outside the tuple, whitespace, line endings and unrelated values remain character-for-character unchanged. Nested parentheses, brackets, braces and escaped quoted text are supported. Lookup follows the legacy last-occurrence rule; editing a duplicate key is refused rather than selecting an ambiguous occurrence. Case aliases in a single edit request are also refused. Unicode identifiers and values are retained.

The supported source has exactly one `OptionSettings=` assignment under the PalGameWorldSettings section, balanced delimiters and valid setting identifiers. Ambiguous marker lookalikes before the assignment, multiple assignments, unsupported syntax and malformed input are refused without mutating the original. This is deliberately not a claim to support every possible INI dialect. It never rewrites an unrecognized document into a guessed shape.

Replacement values are complete serialized expressions supplied by trusted Host code. A structural check requires one entry and rejects closing-delimiter, sibling-key, section and comment injection. The document does not validate game semantics, authorize callers or implement password actions. Raw `Get` and `Serialize` results are internal Host model data and must never be exposed through a normal DTO, error, audit or log. The object is not a record and its default string representation contains no document text. The [Host observation mapper](v0.5-settings-contract-mapping.md) enforces positive nonsecret classification. Later saves must enforce explicit secret unchanged/replace/clear handling.

Resource limits are 1,048,576 characters, delimiter depth 64 and bounded aggregate edit input. These are parser limits, not game setting ranges. Edits are indexed by key to avoid quadratic scans. Documents and key snapshots are immutable; all output is reparsed before return. Constant exception messages omit source and replacement values.

Eight self-test groups cover exact preservation, additions, Unicode, duplicates, injection and malformed-source refusal, resource bounds, 500 seeded nested preservation cases and 10,000 explicit edits. Empty final values can be filled while adding settings in either request order without colliding at the closing offset. The [byte snapshot](v0.5-preserved-settings-encoding.md) separately preserves supported file encodings and BOMs. No file IO occurs here: protected atomic disk replacement, revisions, stopped-state checks, durable operation recovery and approved ViewServer/EditSettings Host APIs remain subsequent #47 work. This component alone does not complete #47.

The Astra trial used no external GitHub Codex reviewer. Astra was responsible for both implementation and technical review.
