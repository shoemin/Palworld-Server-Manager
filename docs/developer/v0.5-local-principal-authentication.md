# LocalPrincipal authentication primitive

Astra #42c1 implements the per-connection proof from [architecture section 3a](v0.5-architecture.md#3a-local-caller-identity-persistent-per-principal-model-client-credential-separate-from-host-verifier). The [local security RPC adapter](v0.5-local-security-rpc.md) binds authentication and enrollment primitives; the [production Host service](v0.5-host-service-composition.md) exposes it, while ordinary-client composition remains #42d3c2. This module must be created only for an already server-authenticated TLS connection, with native identity from the platform connection feature. A request body cannot supply that native identity.

## Selected public framing and client keys

The allowed implementation choice is BCL ECDSA NIST P-256 with SHA-256. Public verification keys are canonical base64 of DER SubjectPublicKeyInfo. Signatures are exactly 64-byte IEEE P1363 fixed-field encoding. The ordinary-client generator exports its private key as PKCS8 for the existing per-user DPAPI store; the Host never imports or stores that private format. Client buffers remain caller-owned and must be cleared after use.

The ASCII signing payload has five newline-separated fields, without a trailing newline: `PSM.LOCAL.AUTH/1`, lowercase D-format HostId, lowercase D-format LocalPrincipalId, canonical base64 32-byte connection binding, canonical base64 32-byte challenge nonce. The Host generates both random values; the connection binding remains fixed for that connection and each challenge gets a new nonce. The client signer checks the exact domain, expected HostId, its persisted principal binding, both nonce encodings and its own public/private key consistency before signing. It refuses arbitrary or cross-Host payloads. Contracts owns only the public challenge encoder. Client.Platform.Contracts defines the generator/signer seams; Client.Platform.Windows implements them. Core owns the pure public-proof verifier used by Host-side code, while Host owns authentication decisions. The independent client-side parser and Contracts encoder preserve the exact project graph; their interoperability is tested.

This uses the documented BCL [signature format](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.dsasignatureformat?view=net-8.0) and [SPKI import](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.ecalgorithm.importsubjectpublickeyinfo?view=net-8.0). The verifier bounds input, checks full consumption, the exact curve and canonical re-export; private blobs, another curve, trailing bytes and noncanonical encodings are rejected.

## Connection lifetime and identity

Each TLS connection owns one disposable authentication object. Issuing a challenge clears earlier authentication and supersedes any pending challenge. Every verification attempt consumes the nonce, including wrong-signature attempts; a 30-second monotonic deadline rejects expired challenges. The connection lock prevents concurrent reuse. Returned challenge bytes are a copy, so request-side mutation cannot change retained verification state. A failed reauthentication leaves the connection unauthenticated; disposal permanently closes it.

The read-only repository opens its own non-pooled SQLite connection in read-only mode, releasing its file handle when the lookup ends. It never creates a missing database/root and only returns active principals on an initialized Host with exactly one active Owner, checked in the same query snapshot. Before issuing or accepting a proof, the Host checks the authoritative HostId, exact stored native principal, canonical current public key and claimed LocalPrincipalId. A key change between challenge and proof rejects that attempt.

Every subsequent `GetCurrentPrincipal` call reads the current persisted state again. Revoked, absent, mismatched or changed-key state clears prior authentication; an observed rejection cannot be undone merely by later restoring a row. The resulting identity and current Owner flag are a snapshot, not a reusable authorization token. Callers must invoke the hook for each request and perform mutation-specific authorization within the mutation transaction. No capability grant is issued or inferred from transport access, successful authentication, a non-Owner identity, or OS administrator membership.

Failure reporting is a required bounded enum callback. It can report suspicious native-identity mismatch without emitting the SID, nonce, signature, key or any bearer secret. The production composition must connect it to its audit/logging boundary; it is not itself a durable enrollment/recovery audit writer.

## Validation boundary

Isolated tests cover distinct owner/non-Owner identities, unknown/revoked/uninitialized users, native/Host mismatch, wrong and malformed proofs, cross-connection and superseded nonce replay, exact expiry, concurrent single consumption, caller mutation, disposal, fresh-key/state invalidation, selected-key DPAPI persistence/retry/reload, private-format rejection and absence of private material in quiescent Host files. Fixtures seed rows directly under a unique lease; this is explicitly not an Owner bootstrap or multi-user field-acceptance claim.

The existing actual Windows service/two-user TLS and storage suite must remain green. Real multi-user LocalPrincipal enrollment, bootstrap and Owner recovery over the final production service are still required by #42's later composition gate.
