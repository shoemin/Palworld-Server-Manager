# Bounded Windows file reads

Trial reference: #47. `IBoundedFileReader` is a Host-side platform seam for existing local files. It has no production settings caller yet. The caller must supply a trusted, authorized root and fixed relative components; this primitive does not choose managed roots, validate their ACL policy, authorize clients, prove stopped state, assign revisions or save files.

The Windows implementation validates the drive-qualified root, refuses mapped network/unknown drives and copies all path components before IO. Empty/dot/device/alternate-stream/separator/control/trailing-dot-or-space components are refused. Starting at the local drive root, it opens each existing component relative to the preceding retained directory handle. Every object is opened without reparse following, then checked on that same handle. Directory junctions and other reparse objects are refused. The leaf must be a disk file with exactly one hard link. No path is reopened after checking, no file is created, no ACL is changed and no privilege or backup-intent retry occurs.

File and ancestor handles omit write/delete sharing until completion. Existing ordinary writers cause refusal; attempted ordinary writes, deletion and directory replacement while held are denied. The reader checks size before allocation, accepts a caller bound from zero through 4,194,308 bytes, reads exact bytes and checks EOF/identity/size again. Cancellation or failure clears an allocated result buffer and releases all handles. Successful bytes belong to the caller and are not cached. These checks do not exclude a previously created writable memory mapping or establish an atomic filesystem/database snapshot; stopped-state and protected-root policy remain independent requirements.

Errors contain one fixed message and a closed failure category, never a submitted path, file contents or an inner native exception. Missing files are distinguished from denied/busy/unsafe/oversized/unavailable reads. The API does not infer defaults from failure and does not return partial bytes.

Tests use actual Windows files, junctions, hard links, denied ACLs, sharing conflicts and retained-handle replacement attempts, plus bounded binary reads, malformed names and cancellation. Fixture ACL restoration is explicitly applied and read back. This is not a real Palworld, privileged-service file-access, settings endpoint or release qualification.

Primary API references: [NtCreateFile](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile), [CreateFile sharing and flags](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), and [handle-based file information](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandle).
