# Windows generation transition composition

Trial reference: #44x, within #44. `WindowsHostComposition.CreateNetworkTransitions` connects the [Host transition coordinator](v0.5-host-generation-transitions.md) to the existing Windows protected credential store, credential material adapter, native TLS cache, authoritative trust reconciler and full-network generation factory. The caller retains the machine lease, store and native PAKE provider through complete owner shutdown. The explicit public publisher is supplied by the same trusted root. A production caller uses the Windows protected publisher; the service qualification wraps that actual publisher only to inject a bounded failure.

Composition requires exact Host/database, service and activation-group identities, explicit named pipe and peer/pairing bind endpoints, a PAKE provider and a concrete activation hook. Missing mandatory collaborators are rejected before work. Endpoint objects are copied for the owner's configuration. Each initial/recovery/replacement startup reconciles the authoritative projection and retained native references, validates protected Current material, loads its matching native certificate and transfers it directly to the generation factory. Failure during generation startup remains owned by that factory. There is no new private-key representation, client holder, production no-op hook or automatic credential regeneration on failure. Reconciliation honors existing retirement metadata; this unit never advances a rotation to Completed or changes retirement eligibility.

The installed `RunAsync` still selects the local-only generation. This explicit full-network factory does not enable service peer ports or create a locally authorized action dispatcher. Those remain separate integration work; the canonical #45 activation hook must be supplied before real Active defaults can be applied.

`WindowsGenerationTransitionQualification` runs inside the existing disposable service account and machine lease, after the earlier standalone cutover qualification and before the main native-TLS fixture listener. It uses a separate child database, known fixture key references, actual Windows protected store/material/cache/publisher and ordinary public trust reader. A synthetic Owner and genuinely empty peer set keep authorization fixtures explicit. A refusing PAKE factory and throwing activation hook cannot provide pairing proof or ordinary authority.

The scenario changes the caller's original endpoint objects to an occupied port after composition; copied owner configuration must still start all three listeners. It negotiates local TLS against the real descriptor. It prepares/stages real New material, injects failure at final New publication after the cutover transaction, and checks Quiesced state with actual Old+Pending publication while SQLite says Current New/CutOver. While Quiesced, first-instance creation of the old named pipe and exclusive binds to both old TCP ports must succeed, independently of the public phase/endpoint report. No connect timeout is accepted as listener-closure proof. Explicit recovery must reconcile actual native/protected material, publish New and negotiate local TLS again. Both protected/native keys remain, New keeps its native key name, and exactly one cutover audit and zero grants are required. Final stop precedes fixture-only key/database deletion. If closure fails, this fixture refuses key deletion; the outer harness can clean only after the disposable service process exits.

The service's existing readiness flag now requires both rotation qualification paths. The main fixture then restores its own `tls-current` descriptor before publishing readiness, preserving the original two-user/ACL checks. Exact passing runs are recorded in the trial ledger. This is service-platform fault injection, not a live Owner ceremony, crash at cutover, reboot, physical multi-Host acceptance or product old-key retirement.

The optional [concrete Windows discovery configuration](v0.5-windows-discovery-configuration.md) now creates a fixed receiver/broadcaster runtime per generation when an explicit UDP port and compatible IPv4 Any TCP binds are supplied. Endpoint deep copies precede validation/capture. Null remains disabled, and installed service enablement/default configuration is still separate.
