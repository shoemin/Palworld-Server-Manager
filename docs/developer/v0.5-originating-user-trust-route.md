# Originating local-user trust administration

Trial reference: #28. `ReadRemotePeerTrust` and `RevokeRemotePeerTrust` route a protected ordinary local client through its own Host to the [receiving peer methods](v0.5-peer-trust-administration-rpc.md). The configured local generation offers explicit `LocalRemoteTrustAdministration` (22) with local protocol1.18; local-only composition omits it. The peer requires its independent feature21 with peer1.15. A capable older-minor client may negotiate the explicit feature. Immutable host1.19/local-security1.18 descriptor additions preserve older schemas; existing public peer reply DTOs are reused.

The original runtime-owned local TLS/native session derives the actual principal. A fixed asynchronous helper requires that current principal's `ManageTrustedManagers` for the exact destination Host before any contact. The Owner still needs an Active destination; local Owner authority cannot bypass the receiver's independent machine ceiling. Wrong local target, a local-Host grant, `ManagePermissions`, or a remote machine grant alone cannot authorize outbound contact. No denied ordinary request triggers a recovery-contact hook.

The generation-owned native sender opens a fresh pinned mutual-TLS connection and captures original completed local/peer fingerprints and incarnation. It requires current Active non-recovery ordinary trust, exact bounded semantic peer negotiation, and feature21. Immediately before the fixed command it rechecks the original peer proof and the current local principal's exact permission. It checks both again before returning. One fifteen-second cancellation bound covers negotiation, command and validation; the awaited generation lifetime retains credential ownership through actual transport/callback disposal. Cancellation is not treated as proof of cleanup. No synchronous permission facade crosses an await or survives its callback.

Requests contain only bounded reachability, semantic destination, and either page cursor/limit or selected peer/revision/incarnation. No actor, Owner, key or proof is accepted from the ordinary client. All authoritative mutations remain on the remote Host through its existing canonical writer and actual receiving machine permission. Existing legitimate native credential observation may independently commit during contact; it creates no grant and cannot turn a denied command into success.

Replies must match the original authoritative destination and selected target. Pages are capped at the requested limit up to16 and16KiB, with unique ordered canonical IDs, positive incarnations, nonnegative revision, closed states, bounded public fingerprints and a progressing continuation matching the last full-page row. A revocation result can never regress revision/incarnation. An unchanged result must match both expectations exactly. A changed result may retain one or both values when the canonical writer retires only residual grants or recovery markers from an already-revoked relationship. No reply is an authority permit.

A remote mutation can commit before local permission changes, cancellation or reply loss. Final local checks can then refuse reporting; they cannot roll back that remote commit. There is no automatic retry or offline queue. Intentional remote self-revocation may return its exact committed result, while subsequent ordinary contact is refused. A reciprocal notice may independently revoke local trust and also make final reporting fail. Responses describe only the receiving Host's local effect, never a two-Host atomic outcome. Remote error details are replaced with constant local text; stale policy and permission refusals retain bounded status classifications.

Nine qualification groups cover actual local native TLS through two real Host generations, explicit feature/old-minor/local-only/anonymous refusal, zero outbound connections for denied local users despite a machine grant, local-only and remote-only permission denial, Owner inability to bypass the receiver, exact selected-peer revoke/idempotence, local permission loss while negotiation is held preventing any command, independently committed remote revocation during a local verifier change, self-revocation/stale requests, malformed reply correlation and bounds, canceled/stopped admission, and generation shutdown while an actual request is held by the receiver. Historical verified peer bindings are explicit fixture inputs; genuine PAKE and process/key lifetime qualification remain separate existing evidence. Controlled middleware barriers and reply-validation unit cases are not relabeled physical-network fault tests.
