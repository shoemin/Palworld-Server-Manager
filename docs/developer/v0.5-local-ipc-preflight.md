# Windows local IPC preflight — Astra #42a

This is the required architecture §3a transport/identity spike, not production authentication or completion of #42. `LocalIpcSpike` lives only in SelfTest. It creates a fresh unique pipe and synthetic certificate, uses Kestrel HTTP/2 over TLS, and has one probe handler that returns the native caller SID. It creates no principal, enrollment ticket, capability, server operation or product listener.

The selected candidate stack is .NET 8 Kestrel `ListenNamedPipe` plus `UseHttps`, with `CurrentUserOnly = false` and a protected `PipeSecurity`: server identity/Administrators/SYSTEM may create instances; the dedicated group gets read/write connect rights, and Network SID is denied. Ordinary clients connect to `.` through `SocketsHttpHandler.ConnectCallback` using Identification-level tokens. `IConnectionNamedPipeFeature.NamedPipe.RunAsClient` reads the native SID synchronously, performs no privileged action, and returns immediately to the server identity. Production authentication must still verify the per-principal signed challenge and its stored SID; native SID is defense in depth, never enrollment or authority.

The probe client checks an exact synthetic certificate SHA-256 pin before sending its HTTP/2 POST. A wrong pin must fail TLS with an authentication error; the probe handler's invocation count must remain unchanged. This test-only whole-certificate pin does not finalize production Host credential fingerprint format or substitute for the required protected public descriptor. No TCP endpoint is configured.

## Findings and validation

- Initial local attempt with `X509KeyStorageFlags.EphemeralKeySet` failed: Windows Schannel reported that the platform does not support ephemeral keys (inner status 0x8009030E). This was a real failed test, not absence of transport support.
- Loading the synthetic PFX with `DefaultKeySet` allows TLS and native-SID identification on this Windows/.NET 8 environment. The test clears exported PFX buffers and tracks the exact CNG key container, deletes it after the server stops, and verifies it no longer exists. This is a test credential only. Production must explicitly account for native key storage/ACL/crash cleanup; it must not describe this loading path as memory-only or silently assume #27's blob ACL also protects a separate container.
- Local full suite: 180/180 PASS before the additional explicit native-container cleanup assertion; focused spike with that assertion PASS. Release compilation clean. Real two-user Windows CI remains required before declaring the spike accepted.
- Real integration will first deny an actual nonmember, accept user A, add user B to the test group and create a new logon, then verify both users report their distinct real SIDs. Both authorized users also try wrong pins; only the two authenticated requests may reach the handler. All identities/groups/pipes/keys are test-only and cleaned up.

Production machine-credential loading, protected public descriptor publication/reconciliation, actual Host service composition and signed per-principal authentication remain subsequent #42 units. The spike's self-signed test credential is never used as a development fallback for the product.

References: [Microsoft Kestrel named-pipe documentation](https://learn.microsoft.com/en-us/aspnet/core/grpc/interprocess-namedpipes?view=aspnetcore-8.0), [runtime Schannel ephemeral-key limitation](https://github.com/dotnet/runtime/issues/23749). Installed .NET 8 reference assemblies confirm `IConnectionNamedPipeFeature` is available; actual native-user evidence, not that API's existence alone, decides the cross-check.
