# Discovery availability and cleanup failures

Trial reference: #44ad, within #44. `LanDiscoveryUnavailableException` identifies a known Windows discovery availability failure after the public operation's owned cleanup. The [owned Host runtime](v0.5-host-discovery-runtime.md) may retry later using fresh observations and the same explicit configuration. The exception does not promise recovery, prove delivery, authorize a fallback route or replace cancellation. This unit adds classification, not retries or periodic Host startup.

Classification occurs only at actual Windows socket creation/setup/send/receive and native-inventory call sites. The closed Winsock set covers network down/unreachable/reset, host down/unreachable, connection aborted/reset, timeout, unavailable source address, socket-buffer pressure and subsystem not ready. Access denied, port collision, invalid parameters/options, message-size errors, cancellation and unknown errors stay outside that set. Native inventory recognizes only `ERROR_NO_DATA` (232) and `ERROR_ADDRESS_NOT_ASSOCIATED` (1228). The values and meanings follow [Microsoft's Winsock error reference](https://learn.microsoft.com/en-us/windows/win32/winsock/windows-sockets-error-codes-2) and [GetAdaptersAddresses](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getadaptersaddresses), with the native inventory values independently checked in the Windows SDK.

Socket setup is owned by one helper: any setup error triggers disposal of the acquired socket before escaping. If disposal fails, the original and cleanup errors are retained together as an aggregate. Sender rounds still await each send and dispose before returning. Receive failures still close the socket and await worker/callback/cancellation cleanup before `Completion` and repeated disposal observe the failure. A cleanup failure always has a fatal outer aggregate, even when its inner exception uses the unavailable type. Owners must not search inner exceptions for a reason to retry an aggregate.

Arbitrary Host callbacks are not treated as native IO. A raw callback `SocketException` stays a callback failure; a callback that itself throws `LanDiscoveryUnavailableException` is wrapped as a non-retryable callback failure. Combined temporary IO and cancellation/disposal failures remain aggregates. Packet source/interface qualification, 512-byte bounds, explicit outgoing interface, TTL and directed-broadcast restrictions remain unchanged.

Three ordinary scenarios exercise the complete socket-error enum against the closed set, known/unknown native inventory codes, synchronous/asynchronous origin mapping, actual exclusive loopback socket release after injected setup errors, combined setup/disposal failure, callback-origin refusal, receiver terminal cleanup and sender-round disposal. A negative test initially reproduced a cleanup-only unavailable exception escaping with a retryable outer type; the corrected implementation always aggregates cleanup failures. This defect was found while introducing the new type, before merge. Existing real sender/receiver probes remain required. Injected error codes and actual loopback cleanup are not evidence of live interface recovery, reboot, physical broadcasts or multi-machine delivery.

The [receiver](v0.5-windows-discovery-receiver.md), [sender](v0.5-windows-discovery-sender.md) and [unverified directory](v0.5-host-discovery.md) are composed by the owned Host runtime with bounded retries, fresh receivers and fully observed shutdown. Host generation wiring must still own that runtime and drain it before credential transitions. No installed port, grant, private credential, authoritative write or Linux production work is introduced.
