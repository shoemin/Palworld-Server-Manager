# Managed settings file observations

The trusted Host-side `IManagedServerSettingsReader` binds a registered profile to the protected managed storage container. Windows accepts only the exact Host-generated `root/<profile N>` spelling, including case, and opens fixed relative paths through `WindowsBoundedFileReader`: `Pal/Saved/Config/WindowsServer/PalWorldSettings.ini` and `DefaultPalWorldSettings.ini`. It never opens the supplied inventory path directly. Null, legacy, alias, foreign-profile and noncanonical paths fail before filesystem access. The public Windows constructor requires the protected Windows root policy; the injected root/reader constructor is internal for qualification.

This adapter is not an authorization boundary or an RPC. A future consuming Host reader must verify the fully qualified local ServerRef and current registration, authorize ViewServer before IO and before returning, serialize observations with revision/save work, and use the existing nonsecret-only DTO mapper. EditSettings does not imply read access. Incoming remote reads need the destination ceiling; the originating Host also checks its local principal. Raw bytes can include secrets and never belong in responses, diagnostics or audit payloads. There is currently no production endpoint invoking this adapter.

Root validation runs before acquisition and again before return. Each underlying file read retains directory handles, refuses reparse objects and multiple hard links, bounds allocation to 4,194,308 bytes, and checks its exact handle after reading. Active configuration is mandatory. Only NotFound for the installation-default source becomes an absent observation; denied, busy, unsafe, oversized, changed and other failures refuse the whole read. Empty defaults remain distinct from missing defaults. Neither absence invokes the legacy copy/create-on-read loader.

The returned non-record object owns the buffers. Failed acquisition clears all acquired buffers, and disposal clears both arrays, including retained read-only views; access after disposal throws. Consumers must use one owner/lifetime, never race access against disposal, and dispose after parsing/mapping. This is not complete memory erasure: parsers can make copies and strings, and the OS can cache file contents. Failures expose fixed bounded-read messages without inner paths.

The pair contains two separately observed files, not a transactionally consistent filesystem snapshot. Root policy checks are observations, not retained policy locks. Privileged changes and pre-existing writable memory mappings remain outside the stronger claims this adapter deliberately does not make. A read does not prove the game stopped, freeze content, grant raw OS access, issue a revision, or implement a save. The future Host save path still needs fresh content reconciliation before stale-token comparison, current authorization, operation/stopped lifetime and durable filesystem recovery.

Validation covers closed routing before IO, optional defaults versus every closed failure code, failed/cancelled/final-policy buffer clearing, disposed views, actual Windows byte/timestamp preservation, missing-active no-copy behavior, unsafe default objects and writer exclusion. Actual service integration repeats protected reads on all four service starts, proves mismatch/missing-active refusal and unchanged bytes/timestamps, and checks that both real unprivileged users cannot read the raw settings or use this protected adapter. Full fixture cleanup remains mandatory. This does not qualify a settings RPC, real Palworld execution, Windows feature parity or Linux support.
