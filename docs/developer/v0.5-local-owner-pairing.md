# Local Owner pairing foundation

Trial reference: #44ah, within #44. The current Host generation offers named Owner-authorized discovery, invitation creation/cancellation and address/code pairing actions. These internal foundations accept the actual local connection authentication and derive the exact Host/principal/native identity/public verifier from it. They expose no caller-supplied actor over the wire. Ordinary local RPC integration and installed remote enablement remain outstanding.

Every action enters the generation's whole-operation lifetime and reads the currently authenticated principal and active Owner. The repository also requires the initialized exact Host, exactly one active Owner and a current non-retired Host TLS credential. Discovery returns only unverified endpoint hints. Invitation creation rechecks the captured Owner after creating the code; cancellation or changed authorization before return cancels the invitation and disposes its redacted secret, retaining cleanup failures. No SQLite transaction spans invitation creation or its audit callbacks.

Outbound pairing checks the Owner before opening the existing first-contact transport. The actual TLS and native PAKE proof still determine the peer identity and public key. After proof, the final immediate writer transaction checks the captured Owner identity and verifier again, after any writer queue wait and before expiry or binding writes. A changed Owner credential refuses the local binding. This check applies equally to new, resumed and replacement dispositions. The existing inbound code-authorized binding path remains separate. Successful pairing creates no management grants; activation and the mandatory #45 hook remain separate.

Actions bind directly to their current generation. A future incoming local RPC must use these authenticated methods and must not queue behind a transition semaphore whose cutover is draining that same RPC. Shutdown waits for the whole action, including transport and audit cleanup. This unit does not change existing post-proof persistence/deadline semantics, rotation or key retirement.

Four ordinary scenarios cover exact actor rejection, zero-grant binding, final authorization after a real SQLite writer queue, actual client-key authentication at the generation boundary, and unreturned invitation cleanup. The cleanup test changes authorization or cancels the request at code creation, then uses real first-contact TLS to show that the invitation is no longer advertised: the refusing PAKE factory is never entered. The guarded native suite adds successful Owner pairing and a genuine verified exchange whose local Owner verifier changes immediately before storage; neither Host creates a binding in the refused exchange. These are local qualification fixtures, not physical-LAN or installed-service acceptance.
