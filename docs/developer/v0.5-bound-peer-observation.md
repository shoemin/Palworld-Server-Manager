# Peer observation bound to the original connection

Trial reference: #45j. This prerequisite for the authenticated permission adapter guards the existing ordinary-peer credential observation transaction with the original negotiated PeerGrantMutationActor. It does not create a permission RPC, business operation or new credential-rotation semantic. Trusted Host composition must supply the actual completed-TLS pins and locally captured relationship incarnation; none are request claims. The existing two-argument observation API retains its established trust-maintenance behavior.

The new overload checks exact Host, distinct peer, valid public pins and positive original incarnation. Inside the same immediate transaction that may promote Pending or record lapse, it checks initialized current local Host credential, original relationship incarnation and current Active/non-recovery peer credential. It reads the authorization revision and computes expected post-observation trust from that initial record. A current pin before expiry is a no-op; first current-pin observation after expiry marks reconfirmation required; already marked retry is a no-op. Actual trusted Pending presentation promotes even after lapse, preserves the rotation ID for its separate receipt and retains the same relationship incarnation. Claimed status never promotes.

After observation, the new path rechecks original connection proof, exact expected trust and revision (one advance for the one trust update, zero for a no-op). It validates every field of the newly created audit and, on promotion, credential-history row by their generated identities. Audit stores the existing controlled peer/Host event; public old fingerprint remains only in its intended history field. Removed/modified audit or history, extra policy writes, late local credential/incarnation/trust changes, missing revision state and cancellation roll back all effects. The audit helper now returns its generated identity; existing callers and fields are unchanged. No grant is created and both local-user/remote-machine capability checks remain required separately.

Four actual SQLite scenarios cover current/lapsed/pending behavior, exact actor/history/state/revision and idempotence; wrong Host/pins/incarnation/self-peer and PeerBound/revoked/recovery refusal; twenty audit/history/proof/policy mutation cases with successful retry after rollback; cancellation before/after observation, eight competing promotions with one winner, and missing revision refusal. Controlled proof fixtures do not prove a new installed RPC or real multi-machine execution. Existing real transport/native/service regressions remain required. The [authenticated Host dispatcher](v0.5-authenticated-permission-dispatch.md) calls this guarded overload before its fresh canonical permission action. Accessibility is waived; physical parity, Palworld, Linux and release qualification remain downstream.
