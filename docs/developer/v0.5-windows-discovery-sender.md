# Constrained Windows discovery sending

Trial reference: #44ac, within #44. `ILanDiscoveryBroadcaster.BroadcastAsync` performs one awaited round with no timer, background worker or retained socket. `WindowsLanDiscoveryBroadcaster` requires a configured port from 1 to 65535 and copies a public packet of 1–512 bytes before asynchronous work. The returned count means that local sockets accepted complete datagrams; it never proves delivery, identity or trust.

The production broadcaster uses the native [Windows LAN policy](v0.5-windows-lan-policy.md) and considers at most 256 observations per read. Exact duplicate links collapse. Each candidate gets a transient socket bound to its observed source address. The socket sets and verifies the explicit outgoing interface, TTL 1, broadcast enablement, no-routing and no-fragmentation options. The Windows SDK `IP_UNICAST_IF` value is 31; setting it uses network byte order and reading it returns host byte order. Zero, unspecified or over-24-bit interface indices are refused. See Microsoft's [IPv4 socket options](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options).

After socket setup, a fresh native observation must still contain the same LUID, GUID, interface index, local address and prefix. A disappeared or changed link is skipped and its socket closed. A destination is always that link's subnet-directed broadcast and the configured port. The limited broadcast address `255.255.255.255` and computed loopback destinations are excluded, including broad prefixes that produce them. Microsoft documents that the [limited broadcast address sends on all interfaces](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-sendto); there is no fallback to that address or to an unspecified interface. No-routing alone is insufficient as a routing guarantee, so source binding, checked interface selection, TTL and the directed destination remain required together. Observations are not atomic authority over later privileged network reconfiguration.

Each send is awaited before its socket is disposed and before another candidate opens. Cancellation stops further work and remains observable after cleanup. Fresh-observation, setup, partial-send or send failures propagate; disposal failures are preserved alongside the original error. No automatic retry, delivery confirmation or installed enablement is introduced. The future Host-owned periodic loop must await the whole round, choose its retry policy and own cancellation. Only public discovery codec bytes belong in this interface; no pairing code or private credential is required.

The ordinary `--windows-lan-broadcaster-probe` separates two kinds of evidence. Synthetic hardware observations and fake owned senders exercise copying, duplicates, the 256-link bound, exact post-setup identity refresh, broad-prefix refusals, cancellation, partial sends and combined send/disposal errors. The concrete Windows socket independently sends real 512-byte loopback UDP, verifies option readbacks and actual source/interface metadata, refuses a pre-cancelled send and proves closure through exclusive rebinding. Production selection hardwires the native reader and real socket factory. Tests send no physical-LAN broadcast and do not establish multi-machine delivery, VPN isolation under live reconfiguration or packet-capture TTL evidence.

The [availability boundary](v0.5-discovery-availability.md) classifies known native failures only when owned cleanup succeeds; callback, unknown and cleanup failures do not become retryable. The [receiver](v0.5-windows-discovery-receiver.md) and [unverified directory](v0.5-host-discovery.md) remain separate. The [Host runtime](v0.5-host-discovery-runtime.md) owns periodic broadcasting and receiver recreation. [Host generation ownership](v0.5-generation-discovery.md) is integrated; local authorization/installed ports, key retirement and physical field qualification follow. Discovery cannot grant authority; negotiated pairing and pinned TLS remain the trust boundaries. Linux remains gated on Windows parity.
