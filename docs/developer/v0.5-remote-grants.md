# Authenticated remote grant writers

Trial reference: #45g. This unit adds trusted incoming-peer repository entry points for direct Host grants, direct server grants and atomic presets. It builds on the [canonical rules](v0.5-authorization-foundation.md), [transactional writers](v0.5-transactional-grants.md), [presets](v0.5-canonical-presets.md) and [creator policy](v0.5-creator-grants.md). [Authenticated Host dispatch](v0.5-authenticated-permission-dispatch.md) is implemented. Host RPC wiring and actual originating-user outbound enforcement remain separate work; no server operation or UI is enabled.

`PeerGrantMutationActor` contains the Host-owned completed TLS/negotiation evidence: exact local Host and peer IDs, actual remote/local public fingerprints and original relationship incarnation. It is never deserialized from a request. The caller holds the authoritative Host lease. Every writer independently checks initialized Host/current unretired credential, Active/non-recovery peer, trusted presented remote pin and exact incarnation inside its immediate transaction, before authorization and again after audits. Existing trusted pending-pin live presentation semantics are unchanged; no trust/rotation promotion occurs in these writers. The same check continues to guard creator finalization.

`IssueRemoteHost`, `IssueRemoteServer` and `ApplyRemotePreset` construct the real RemoteManager actor internally. Private adapters share the direct/preset transaction logic with authenticated local writers; no public caller can supply an actor-kind switch, authority validator or policy snapshot. Incoming requests must target this authoritative Host, including the Host component of ServerRef. Local writers still support local-user permissions for an explicitly remote target; an incoming peer cannot use these entry points to rewrite that outgoing policy for another Host.

Only existing canonical sources authorize remote delegation: exact parent held by this actual peer, exact capability/type/target and sufficient delegation rights. Every ancestor must remain valid. Remote root grants and ManagePermissions shortcuts are refused. Presets validate every entry against the original snapshot before inserting any candidate, so one new candidate cannot bootstrap another. This adds no remote default-edit, historical reissue, Owner mutation or revocation API. The separately approved creator auto-grants remain exactly six use-only Owner roots for newly confirmed successful creation; this change does not expand that bundle.

Expected permission-policy revision is mandatory. Inserted grants and success audits commit together, identifying the actual peer and exact issuer/source/grantee/target/rights. Presets use a generated correlation ID, never their presentation label. Fingerprints, native identity/verifier material and other secrets are excluded. Final peer proof, exact revision increment and exact saved grant checks precede cancellation and commit. Audit failure or any detected source, principal, peer, incarnation, local credential or candidate mutation rolls the complete effect back. Empty presets authenticate/check revision but write nothing; stale writes require refresh.

Seven actual SQLite scenarios qualify exact delegated effects and peer audit; root/capability/type/scope/rights/source-holder refusal; current proof/trust/revision at all three entry points; single and last-preset-audit failures and seven authority/effect mutations; atomic per-entry validation/no candidate bootstrap; eight concurrent writers and exact later subtree invalidation; empty/cancellation/trusted-pending evidence. Full regression checks cover shared local direct/preset, configured defaults, historical reissue and creator finalization. These controlled fixtures supply simulated completed transport evidence: they are not proof of installed remote permission RPCs, physical multi-machine creation, Windows feature parity or release readiness. Accessibility is waived; Linux remains gated.

[Pre-write permission denial auditing](v0.5-permission-denials.md) now commits a denial-only record for an authenticated policy refusal before any requested mutation. No requested grant/default/history/invalidation/creation effect commits on refusal. Authentication, malformed/stale/cancelled requests and later mutation/audit failures retain their separate rollback paths.
