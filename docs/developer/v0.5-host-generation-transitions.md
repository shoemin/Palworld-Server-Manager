# Host generation transition coordination

Trial reference: #44w, within #44. `HostGenerationTransitions` belongs to the trusted Host composition root under the existing machine lease. It serializes startup, Host-dispatched work, acceptance collection, full generation shutdown, cutover/publication and replacement startup. Its current generation and cutover handle are private. Named pairing/trust helpers and public endpoint metadata are exposed; the generic trusted work callback receives only cancellation, never the current generation or cutover coordinator. These entry points do not authorize a caller.

The caller must dispatch a rotation action outside the incoming generation's RPC/connection scope: cutover closes that scope and waits for all its work. Awaiting the complete cutover inside the connection being drained would deadlock. A later installed action dispatcher must arrange that handoff, fresh local authorization and client-visible operation ownership. This coordinator does not implement a durable operation identity, operation locks, server actions or that dispatcher.

Before contacting peers, cutover checks the current Owner and exact proposal. It collects actual peer acceptance through the serving generation and checks current eligibility before disrupting service. Blocked pending peers, missing routes, stale authority or insufficient acceptance leave the current generation serving. Once transition begins, it stops the old generation completely, obtains only that generation's collector-bound coordinator, executes the existing final fresh transaction and ordered publication, reconciles authoritative trust and starts the actual Current generation. No competing dispatched action can start a second generation or reuse the old handoff during these steps. A repeat request after completed cutover is refused by the existing staging contract before disrupting the new listener; it is not a new rotation request.

A cutover/publication failure after successful old-generation closure leaves the owner **Quiesced**. Explicit recovery reconciles durable state before any listener starts: before-commit failure resumes Old with the pending projection, while after-commit failure resumes New. Neither failure rolls back durable Current. Failed cleanup, failed reconciliation or failed replacement startup is **Faulted**, cannot recover through this instance, and remains a shutdown failure. The service owner must preserve the lease through cleanup and surface the failure; a later process startup must perform authoritative reconciliation again.

Terminal stop closes future actions, cancels running/queued work and waits its complete cleanup before closing any remaining generation. Repeated stops share completion. Stop during actual startup waits for the candidate to be returned and cleaned before completion; it cannot release the lease while a startup callback still owns resources. An unexpected listener stop closes the entire owner with a reported failure. None of these waits can turn a timeout into successful quiescence.

Nine ordinary scenarios exercise actual old/new local and peer TLS, peer receipts, non-disruptive preflight refusal, public publication failures on both sides of commit, explicit recovery, changed Owner and expired acceptance during blocked shutdown, stop during actual startup, queued work/cancellation failure, unexpected listener closure, failed replacement/reconciliation, competing cutover requests and an actual audit-flush failure that prevents replacement. Synthetic Owner, material and publication callbacks are explicit fixtures; separate Windows service qualification supplies real protected material/cache/publication evidence. The pairing factory refuses PAKE proof in these ownership tests; native success is qualified separately.

This unit does not enable installed peer ports or local Owner actions, replace the mandatory #45 activation hook, retire old keys, modify grants/schema/wire contracts, or establish process-kill/reboot/physical-machine acceptance. Installed dispatch/configuration, remaining #44 integration and retirement remain outstanding.
