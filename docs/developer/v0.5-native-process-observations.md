# Windows process observations

`IProcessInspector` is the architecture's Host-side platform seam. `WindowsProcessInspector` uses a native process-name snapshot and opens only PalServer-prefix candidates for limited query and synchronization access. It observes the full image path and exact UTC creation time through one pinned handle, rechecks exit state, and closes every handle. The Host can later distinguish PID reuse using creation time and verified image identity. No production launch, kill, process ownership or reattachment is added here.

Enumeration failure, inaccessible candidates, failed queries and malformed observations produce an explicitly incomplete result. Discovered processes can still be reported alongside that uncertainty. A candidate already gone may be omitted. The image reached through the pinned handle is rechecked for the PalServer prefix, because the enumerated PID may have been reused. No ordinary client receives these raw paths, and observations are never logged automatically.

The result is immutable and includes candidate paths across the whole machine. The inspector deliberately does not decide that a lexical path matches a managed installation: aliases, junctions and other path-identity issues belong to protected Host reconciliation. An unreadable candidate may be relevant to any installation, so it keeps the snapshot incomplete. Even a complete empty scan is only an observation at that moment, not proof of a stopped or finalized server. Host-owned retained handles, durable lifecycle state, launcher/shipping handoff grace, current permissions and operation locks remain necessary before start/save/update/delete. This seam is not yet wired into those operations.

Tests exercise real synthetic Windows processes, exact creation times, distinct installation paths, exit observation and repeated handle disposal, plus injected failed/partial enumeration, query uncertainty, PID reuse, malformed results, defensive copies and cancellation. Synthetic execution is not real Palworld compatibility, service launch isolation or Windows feature-parity acceptance. Frozen v0.4 process behavior is untouched.

Native API references: [process snapshots](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-createtoolhelp32snapshot), [full image path queries](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew), [process creation times](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes).

The separate [retained-handle attachment seam](v0.5-retained-process-handles.md) can later pin one exact observed identity for exit collection. Neither seam alone certifies a finalized server lifetime.
