# Preserved settings file encoding

Trial reference: #47. `PreservedPalworldConfigFile` is a pure Core byte snapshot around the [preserved text document](v0.5-preserved-settings-document.md). It accepts strict UTF8 with or without a byte-order mark (BOM), and BOM-marked UTF16/UTF32 in either byte order. UTF32 recognition precedes UTF16 so their shared prefix is not confused. Unmarked input is interpreted as strict UTF8; the component does not guess legacy code pages.

The component copies input before decoding, verifies that decoding and re-encoding reproduce the exact bytes, and retains the original preamble. An empty edit returns the same immutable snapshot. Explicit value edits retain the original encoding, BOM, line endings and unchanged text; Unicode is not normalized. The accepted text document still checks supported INI structure, preserves unrelated values and refuses ambiguous changes. Password values remain unchanged unless trusted Host code expressly changes them through its later secret-action boundary.

Invalid, truncated or overlong encodings, unpaired surrogates and excessive input are refused. Decoder/encoder fallback exceptions are replaced by constant errors without inner exceptions or byte/text echoes. Input is bounded to 4,194,308 bytes and the existing 1,048,576-character document limit. Returned byte arrays and key snapshots cannot mutate retained state. The class's ordinary string representation contains no content.

Three self-test groups exercise all six supported forms, exact original/edited bytes, combining-character preservation, unchanged unknown/password data, defensive input/output copies, invalid sequences, invalid replacement text and both byte/character bounds. These are in-memory tests. The component has no filesystem, path, authorization, wire or logging API, and exposes no content-derived revision hash. Raw reads and serialized bytes remain trusted Host model data.

Host-controlled file paths, protected reads/temporary files/atomic replacement, revisions, stopped-state checks, durable operation recovery and the approved ViewServer/EditSettings routes remain subsequent #47 work. This component alone does not complete #47, establish real Palworld parity or authorize a release.

The Astra trial used no external GitHub Codex reviewer. Astra was responsible for both implementation and technical review.
