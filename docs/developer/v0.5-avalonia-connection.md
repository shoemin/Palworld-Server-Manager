# Local Host connection in Avalonia

Trial reference: #52c1. The shell's explicit **Connect to This PC** button uses `App.CreateMainWindow` and the existing ordinary `LocalSecurityClient` through its Windows composition root. `ConnectAsync` returns the semantic HostId from pinned local negotiation together with the proved per-user LocalPrincipal identity. It adds no wire method. The channel closes after the check, so the UI describes a verification for this request and invites another check; it does not claim a continuous live connection.

Only the existing proven-missing-pipe path can request `IHostActivation.RequestStartAsync`, once, with bounded negotiation retries. Wrong trust, failed proof and generic transport errors cannot start a fallback Host or create authority. No bootstrap, enrollment, privileged CLI, direct process/filesystem operation or remote connection is reachable from this control. Initial enrollment and recovery remain explicit authorized procedures, not automatic consequences of connecting.

Each attempt clears previous rendered inventory and verified identity. Attempts are single-flight with a sixty-second cancellation budget. Cancel/close cancels the client request and rejects even a late successful reply; it does not promise to stop a service whose start was already requested. Completion restores focus from the disappearing Cancel control. Diagnostics use fixed classifications without raw exception details. Full semantic HostId is selectable on success. The empty shell model is explicitly labelled **inventory unavailable**, because no inventory protocol exists yet; it does not imply zero servers or infer paired resources.

The ordinary self-test suite exercises this public API over the accepted local RPC test fixture, including unregistered refusal, proved Host/principal identity and wrong-pin refusal without activation. Actual Avalonia input tests exercise the rendered connection button, success, fixed failure messages, empty/invalid replies, single-flight, cancellation with late success, focus return and late replies after window close. These UI inputs are synthetic and do not certify real SCM/DPAPI integration. [Rendered connection evidence](../design/astra-52-shell/README.md) uses the actual view and three semantic themes.

The existing actual Windows service/multi-user suite remains mandatory regression coverage. New UI-to-service qualification and native assistive-technology/high-contrast evidence remain #52c2; neither is represented as passing from these injected UI tests. Full #52 remains in progress.
